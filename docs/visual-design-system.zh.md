# 企业级客户端与 Admin 视觉设计系统

[English](visual-design-system.md) | 中文

## 概述

本文定义企业级客户端与平台超级管理员后台共用的视觉与交互系统。它采用 Arivo 高保真参考中的深色画布、冰蓝强调、克制微光和高密度信息布局，并将这些规则映射到现有 `ui-theme` 语义 token。客户端与 admin 共用视觉语言，同时保留不同的信息密度与任务节奏。

本文定义目标设计基线及当前实现 owner。共享主题角色与管理员导航栏消费深色调色板；Admin 内容画布采用[Admin 参考界面对齐笔记](../.agents/notes/implemented/architecture/2026-09-30-enterprise-admin-reference-alignment.zh.md)记录的浅色工作例外。客户端已保存偏好仍选择明色或系统映射。字体栈声明了指定字体，并在本地字体资源不可用时使用平台回退字体。

<a id="scope-and-authority"></a>
## 范围与权威

范围包括 `apps/web`、`packages/client/` 下的企业级客户端包和 `apps/admin`。它适用于这些产品的外壳、导航、内容页、表单、表格、浮层、反馈和响应式行为。

本次任务提供的 `Arivo_Studio_高保真视觉规范_V（3.0）.md` 是深色方向的视觉参考。其产品名称、页面专属构成、单文件 HTML 工作流和截图交付说明不是仓库要求。本文提取可复用的视觉规则，并将其分配给仓库的 token 与组件 owner。

共享源头是 `packages/client/ui-theme/src/styles/`。功能包消费语义别名，不另建全局色板。[Web UI 样式参考](web-styling.zh.md)继续负责浏览器 CSS 的归属，而本文负责跨产品视觉方向与交互词汇。

产品默认呈现为深色。现有 `light` 与 `system` 设置在组合暴露时继续有效；它们只把相同语义角色映射到明色表面，不改变组件结构、交互顺序或状态含义。

<a id="design-principles"></a>
## 设计原则

### 一套共享基础

颜色角色、排版角色、间距阶梯、圆角规则、层级、焦点处理、图标几何和状态含义由客户端与 admin 共享。页面可以选择不同密度或布局轨道，但不能另建局部设计语言。

### 深色表面层级

层级来自表面级别、文字对比、间距和层级效果。不要为了让组件显得重要而添加新颜色，应使用下一个语义表面或更强的交互状态。

### 强调色是信号

冰蓝只用于激活交互、关键数据、进度和环境强调。它不是所有操作的默认按钮填充色。危险红只用于最小范围内确实需要它的失败标识。

### 状态不能只靠颜色表达

每种状态除了颜色还必须使用文字、图标、位置或操作提示。禁用、加载、失败、选中和完成状态在灰度显示和减少动态效果时仍应可理解。

### 高密度但保持安静

企业工作需要扫描和重复操作。保持行对齐、标签简短、控件可预测，并让次要细节保持安静。只有明确的视觉焦点才使用微光和玻璃效果。

<a id="visual-foundations"></a>
## 视觉基础

### 颜色 token

以下值定义目标深色基线。新代码应消费最接近的 `--dsw-alias-*` 角色；这些名称描述设计角色，不允许在功能 CSS 中直接写入颜色字面量。

| 角色 | 目标值 | 用途 |
| --- | --- | --- |
| 画布 | `#141414` | 应用背景与全宽工作区 |
| 一级表面 | `#202426` | 主内容卡、主面板或节点式工作单元 |
| 二级表面 | `#121212` | 辅助面板、通知区域和紧凑状态容器 |
| 三级表面 | `#383C40` | 表面内部的可选择控件 |
| 深层表面 | `#0A0A0A` | 聚焦或高优先级数据面板 |
| 控件表面 | `#0E0E0E` | 搜索、筛选和紧凑输入控件 |
| 按钮表面 | `#131315` | 次级胶囊与紧凑操作 |
| 分隔线 | `#232325` | 轨道、分隔线或弱结构规则 |
| 一级文字 | `#FFFFFF` | 页面标题、主要数值和操作标签 |
| 二级文字 | `#D3D3D3` | 正文与辅助说明 |
| 说明文字 | `#9B9B9C` | 标签、未激活导航和紧凑说明 |
| 元信息 | `#868C94` | 时间、归属和低优先级元数据 |
| 强调色 | `#68C5FF` | 激活状态、进度、关键数据微光和环境光 |
| 深强调色 | `#4785B2` | 强调渐变中段和低强度强调 |
| 危险色 | `#E06E5C` | 仅用于失败状态文字或失败状态描边 |

中性边框使用现有语义 border 别名，并在浏览器支持时绘制为 0.5px 发丝线。状态色边框在必须明确表达状态时保持 1px。功能组件不得引入第二套强调色、任意灰度或页面专属危险色。

### 排版

中文界面文案使用 `Noto Sans SC`，数字、百分比和短 Latin 标签使用 `Space Grotesk`。字体不可用时沿用现有系统字体栈。

| 角色 | 字体 | 字号／行高 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | Noto Sans SC 600 | 22 / 30px | 主页面标题 |
| 区块标题 | Noto Sans SC 600 | 16 / 24px | 区块与面板标题 |
| 正文 | Noto Sans SC 400 | 14 / 22px | 主要内容与表单文案 |
| 紧凑正文 | Noto Sans SC 400 | 13 / 20px | 密集行、admin 元数据和辅助文案 |
| 标签 | Noto Sans SC 500 | 12 / 18px | 字段标签、标签页和导航标签 |
| 元信息 | Noto Sans SC 400 | 11 / 16px | 时间、提示和次要状态 |
| 关键数值 | Space Grotesk 600 | 22–26 / 28px | 配额、金额、百分比或进度锚点 |
| 代码 | 现有等宽字体角色 | 现有角色 | 终端、JSON 和源代码文本 |

每个字号都必须配套行高。不要使用负字间距。可能增长的文字必须在所属布局中换行或截断，不得覆盖相邻控件。

### 材质与层级

普通卡片使用细描边和共享面板层级。高层级表面设置 `border: 0` 并使用现有 elevation token，使发丝线成为第一层投影。不得在同一表面同时使用中性 border token 与 elevation 投影。

组件微光由三层克制效果组成：深色实底、靠近上方起始边缘的低透明度冰蓝径向高光，以及不覆盖整个表面的颜色变化。它用于激活导航项、明确的主操作或聚焦数据卡。

关键数据微光只用于配额、进度和运行总额等数值锚点。不得将它用于普通正文、所有按钮或所有数字表格单元格。

液态玻璃是可选材质，只用于引导页或空状态主视觉等一至两个明确焦点表面。它不是默认卡片样式，也不得铺满整页。

### 图标

使用现有图标库或图标原语。图标使用统一的 20px 导航尺寸、16px 紧凑控件尺寸或 24px 主要操作尺寸。描边图标使用圆角连接和中性前景色；激活状态由容器表达，除非图标本身表达状态。

所有纯图标操作都需要无障碍名称；含义不明显时还需要 tooltip。已有图标库能表达相同操作时，不要手写 SVG。

<a id="layout-and-responsive-rules"></a>
## 布局与响应式规则

### 页面轨道

每个页面外壳内部使用共享内容轨道。同一任务中的工具栏、页面标题、表格和卡片网格使用相同的左右边界。不得为每个区块单独定义边距公式。

客户端外壳优先保证可读的中央对话区，同时保留导航和可选详情区。admin 外壳优先保证稳定的导航列和用于比较、编辑的宽工作区。轨道宽度可以随视口伸缩，但对齐关系必须稳定。

### 密度

客户端内容采用舒适阅读密度：内部间距 8–16px、交互行高 36–44px，并为流式或创作内容保留更大的呼吸空间。admin 内容采用紧凑扫描密度：内部间距 6–12px、行高 32–40px，并保持表格列的固定对齐。

密度只改变间距与行高，不改变语义组件或状态词汇。同一状态不能因为属于客户端或 admin 就使用不同颜色。

### 响应式行为

窄屏下导航折叠为抽屉或紧凑轨道，次要详情移入抽屉，多列表单变为单列。表格通过横向滚动、列优先级或详情视图保留全部字段；不得静默删除重要数据。

触控尺寸下紧凑控件的点击区域至少为 36px，主要触控操作至少为 44px。仅悬停可见的信息必须有焦点或点击等价路径。`prefers-reduced-motion: reduce` 时减少动态效果。

企业客户端保持固定 56px 一级导航 rail。会话侧栏默认 280px，可在 264px 到 420px 之间拖动，并可独立收起。Workbench 默认 360px，最小 300px，最多占主工作区 80%；对话至少保留 560px，因此窄容器会把 Workbench 打开为右侧覆盖层。

<a id="component-and-state-rules"></a>
## 组件与状态规则

### 外壳、导航与标题

顶部栏负责产品身份、工作区或作用域上下文、全局状态和账号操作。侧栏负责稳定导航。页面内容从一个明确标题开始，可带说明和该页面的主要操作。

导航项具有默认、悬停、焦点、激活和禁用状态。激活状态使用组件微光或安静的选中表面；图标不必切换为另一种颜色。分组标签属于次级信息，不能与激活项竞争。

### 按钮与控件

只有当某个操作是当前主要下一步时，主操作才使用强调色或微光处理。次级操作使用按钮表面或带细描边的透明背景。危险操作在确认前使用中性呈现，确认上下文再使用危险角色。

图标按钮保持稳定的正方形尺寸。文字按钮保持短标签，不要变成圆角卡片。打开菜单的按钮使用明确的展开图标，并在触发器中保留当前选中值。

### 输入、筛选与表单

标签位于控件之前，即使已有值也保持可见。帮助文字位于字段下方，错误文字靠近无效字段。只有在标签和校验仍可读时才使用双列表单；长文本、JSON 或跨字段说明可在 admin 表单中使用全宽字段。

筛选器展示当前范围，并提供清除路径。可能使未保存工作失效的变化需要明确确认或可见草稿状态。提交时的错误汇总不能被行内校验替代。

### 卡片、行与表格

卡片只承载一个任务或一个摘要。不得在卡片内再放不相关的卡片。用户需要比较大量项目或重复操作时使用列表行。表格按列对齐数值，长列表扫描时保持表头可见，并通过键盘可达的方式提供行操作，不能只在悬停时出现。

空状态说明缺少的对象并提供一个下一步操作。加载状态保留最终布局尺寸。错误状态说明失败内容、仍然保留的内容和下一步恢复操作。

### 浮层与反馈

菜单和浮层锚定触发器，保持在视口内，按 Escape 关闭，并将焦点还给触发器。抽屉保留页面上下文；只有重要决策或无法内联表达的内容才中断页面使用对话框。

Toast 用于确认操作完成或失败，填充保持中性。失败 Toast 提供受影响对象、简短原因、可用时的定位或重试操作以及关闭操作。持续性问题应留在页面或通知面板中，不应无限堆叠 Toast。

### 状态词汇

两个产品共用 queued、running、ready、failed、cancelled、disabled 和 selected 状态词汇。状态标签包含文字或熟悉的图标，不能只依赖色相。running 可以使用克制的强调微光；failed 只能在标签文字或描边上使用危险色。

<a id="interaction-rules"></a>
## 交互规则

每个任务都有一个明确入口、一个可见当前位置和一个可恢复出口。改变当前范围的操作要在页面标题、面包屑或选中导航项中展示结果范围。

悬停可以展示次要操作，但不能隐藏主要操作。焦点使用可见焦点环或同等对比度。键盘顺序遵循视觉顺序，Escape 先关闭最近的临时层，再关闭页面级层。

可逆的局部变化使用行内操作。需要保留列表上下文的详情使用抽屉。破坏性确认、凭据输入或短暂聚焦决策使用对话框。完成后将焦点还给发起控件，或移到新建内容上。

长时间操作要展示进度，能力支持时提供取消，并在发起操作所在位置报告最终状态。失败按操作提供重试、检查或反馈入口，不得无记录地消失。

文案由 locale owner 管理。标签、tooltip、占位、错误文案和无障碍名称使用所属字典。除非用户正在操作该技术概念，不要在用户文案中直接暴露实现术语。

<a id="enterprise-client-patterns"></a>
## 企业级客户端模式

### 应用外壳

切换 Session 或工作区时保持导航轨道稳定。当前工作区、Session 和连接状态在靠近外壳边界的位置可见。详情面板在工作区旁打开，关闭后不销毁当前 Session 上下文。

### 对话与流式输出

对话是主要阅读区域。Composer 操作保持成组，流式期间提交操作保持稳定，排队工作可见但不遮挡最新响应。工具和附件结果使用紧凑行或卡片，并保留指向 Session event 的来源链接。

流式、审批、问题和错误状态必须在用户读完全部内容前可区分。临时状态靠近操作，持久历史保留在对话时间线中。

### 文件、任务与设置

文件与交付物根据主要任务在列表和网格间选择：比较优先列表，预览优先网格。任务与工作流在稳定行中展示状态、owner、时间和下一步操作。设置使用分组区块，每行一个控件，并明确展示已保存或待保存状态。

### 账号与组织

账号与组织页面沿用客户端外壳，但使用更紧凑的表单节奏。权限、设备和成员状态必须明确；被阻止的操作说明所需角色或管理员动作。

<a id="admin-console-patterns"></a>
## Admin 后台模式

### 登录与会话状态

登录页保持专注和安静。页面展示产品身份、一个表单、一个主要操作和一个恢复入口。认证错误说明失败步骤，但不暴露秘密。

### 导航与组织树

Admin 侧栏按管理任务分组。组织树把选中与展开作为两个独立操作；选择节点只更新详情区域，不丢失树的当前位置。组织状态使用文字表达，树折叠后仍可理解。

### 表格与详情抽屉

Admin 表格优化扫描：稳定表头、紧凑行、可见筛选和可用键盘访问的行操作。详情抽屉保留所选行上下文；只有记录存在独立详情分组时才使用标签页。关闭抽屉后焦点回到所选行。

### 表单与高风险操作

模型、价格、适配器、组织、邀请和平台设置表单按相关字段分组，并在相关字段附近展示跨字段校验。敏感值保持遮罩，确认文案不得重复秘密。破坏性或不可逆操作使用确认对话框，并写明对象和后果。

### 用量与审计

用量页先展示少量关键总数，再展示趋势、筛选、分组明细和记录。审计页优先展示时间、操作者、对象、操作和结果。图表和摘要克制使用强调色；表格值保持中性，除非它们表达状态。

<a id="acceptance-checklist"></a>
## 验收清单

每个新页面或大幅修改的页面都使用以下清单。

- 页面使用共享的画布、表面、文字、边框、强调和层级角色。
- 页面标题、工具栏和主内容共用一个内容轨道。
- 页面明确主要操作，并保持当前位置可见。
- 每个交互控件在适用时都有默认、悬停、焦点、禁用、加载和错误行为。
- 每个纯图标操作都有无障碍名称，必要时提供可发现的说明。
- 空、加载、成功和失败状态说明下一步，不只依赖颜色。
- 破坏性操作在确认前写明对象与后果。
- 窄屏布局通过抽屉、滚动或详情视图保留同样的操作能力。
- 文字、标签、占位、错误和无障碍名称来自 locale owner。
- 动效遵守减少动态效果偏好，不隐藏状态变化。
- 新视觉值先加入 token owner，再由功能包使用。
- 共享职责变化时同步更新实现映射和所属 README。
