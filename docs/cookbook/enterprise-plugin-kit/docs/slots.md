# Client Slot catalog

English | [中文](slots.zh.md)

This catalog is generated from the shipped Client slot contract. It lists all 57 keys available to a Client package in the current platform release. A key is usable only while its declaring owner is mounted. The JSON file beside this page preserves register options, owner props, framework props, key domains, examples, and source pointers.

## Registration rules

1. Contribute UI only through `ctx.slots.register(options, Component)`; declare `inject: ['slots']` in your returned plugin (object form) or the seat is withheld.
2. Wrap every registration in `ctx.slots.inject(key, () => ctx.slots.register(...))`. A slot exists only while the entry that declared it is mounted, and registering into an undeclared slot throws; `inject` runs your registration when the declaration is (or becomes) live and re-runs it if the owner remounts.
3. Do NOT pass `priority`: the browser-half facade assigns one automatically, and it is LOWER than every shipped entry — in a single or keyed cell that means your entry is the one that renders.
4. You cannot `import` anything, so the design-system components are out of reach: build markup with `React.createElement` and ship CSS through `styles.insert(css)`. Use the theme CSS variables (`var(--dsw-alias-bg-layer-1)`, `var(--dsw-alias-label-primary)`, …) instead of literal colors, or your contribution breaks in the other color scheme.
5. Every component receives the framework hook seats listed under `framework props` for its scope; a selector hook is called with a selector, e.g. `useSessions(state => state.current)`.
6. This catalog is the COMPILE-TIME contract of the shipped web bundle, not a snapshot of one page: a key is registrable only where the owner that declares it is mounted. A failed registration surfaces in the browser-half load report — read it back with `cordis_inspect what:"temporary"`.

## Reading the full contract

Use `slot-catalog.json` as the machine-readable contract when generating a Client package. Its `registerOptions`, `ownerProps`, `standardProps`, `keyDomain`, `hookContext`, `slotInject`, `example`, and `source` fields are part of the release snapshot. A plugin must tolerate an absent owner and must not register into an undeclared key.

The catalog is a release snapshot. The platform must publish a new snapshot with the Client SDK when it adds or removes a Slot.
