# 企业团队管理

[English](enterprise-team-governance.md) | 中文

## 概述

平台管理员在 Admin 开通团队、配置资源和恢复访问。员工在桌面客户端选择团队，开展工作、管理获准的团队资源，并恢复保留的文件或媒体结果。团队承担资金、存储和业务数据；部门在团队内部组织成员与分享。

<a id="identity-and-onboarding"></a>
## 身份与入职

两种部署模式都要求账号在目标团队具有明确的有效成员关系。私有化部署创建一家公司；部门使用公司内的组织单元。成员和角色不沿父组织继承。平台管理是一种独立身份，不隐含授予会话或文件访问权。首次初始化显式授予引导账号平台管理权和团队 Owner 身份；重复初始化不会重建已撤销的授权。

创建团队必须明确选择成员默认预算：非负金额或不限额。Admin 开通时选择已有 Owner 账号及团队／个人容量政策。开通检查报告 Owner、恢复渠道、已发布模型、资金、预算、容量及安装包发布状态。资源政策未完成时不能接纳模型请求。

邀请邮件进入公开的 Admin `/account` 页面。页面支持登录、政策允许的注册、验证邮件、密码找回／重置和邀请接受。公开账号页面提供已发布安装包下载。安装后的桌面客户端通过现有登录流程及显式团队选择接续。邀请持久化与邮件投递分别记录结果；失败邮件可重发，已撤销或过期链接不能接纳成员。重复接受复用原关系。停用关系需要授权恢复，不能用邀请创建新关系代替。

<a id="authorization-and-administration"></a>
## 授权与管理

有效权限合并启用的团队级固定／自定义角色，并扣除显式拒绝。部门角色不授予全团队管理权。成员、预算、账单、存储、身份、审计、插件及内容权限相互独立。每次新增模型调用重新检查成员、团队状态、权限及模型发布范围。目录同样检查全部团队或指定团队范围；已提交的供应商任务保留连接与价格快照。

Admin 使用平台接口管理全局团队、资源分配、余额调整、套餐／席位、Owner 恢复和生命周期。团队目录在服务端搜索、分页，并要求显式选择团队。带版本的治理修改必须填写原因，并追加审计记录。账号身份／密码恢复指定对象，要求显示的版本和原因，审计不记录密码，并撤销浏览器会话、待交换桌面码及已有设备凭据。邮箱纠正默认清除验证状态，除非明确确认。桌面团队管理使用成员接口，预算、容量、角色、身份提供方及审计分别授权。角色和身份配置编辑拒绝过期版本。审计及账本从服务端分页结果读取。桌面管理导航遵循当前能力。页面聚焦及可见页面轮询刷新资源视图；桌面 `activityRefreshMs` 和 Admin `ADMIN_ACTIVITY_REFRESH_MS` 配置默认 30 秒周期。

私有化部署还提供 [Admin 企业 SSO 与目录同步](../../apps/admin/README.zh.md#development)。平台管理身份、显式有效团队成员关系及对应团队权限缺一不可。普通团队成员不能进入 Admin 外壳；开放／SaaS 部署不加载其企业配置资源。

平台[套餐目录](../../apps/api/src/subscription-plans.ts)保存带版本的名称、参考月价、默认席位和可选资源默认值。Admin `/platform/plans` 管理目录；团队套餐操作选择已启用的目录代码及修订号。分配保留资金、账单和资产。编辑套餐不改写已分配团队。删除要求没有引用且不是开通默认套餐；停用阻止新增分配并保留已有订阅。

切换团队先停止旧运行时并清除其凭据，再选择另一团队。恢复保存的选择会重新验证成员资格；失败时不回退到第一支团队。成员停用、Owner 拒绝／撤权、目录同步和 Owner 交接共用最后有效 Owner 保护。目录同步保留全局账号身份，在团队内部创建部门。已批准变更记录修改前的值，供显式补偿执行使用。目录导入要求已有具备登录渠道的账号，不创建无凭据的全局身份。

<a id="monthly-accounting"></a>
## 月度核算

金额使用整数微元与不可变钱包流水。付费请求接纳时检查团队正余额及发起人的本月已结算消费。成员可继承当前团队默认值、使用单独金额或不限额；零元禁止新增付费请求。Owner 仅豁免个人预算。角色变更、恢复、补款及预算调整保留消费。免费价格仍要求授权与发布，但不检查资金或个人预算。

文字和当前媒体任务在结算后完整扣除实际费用。并发接纳的任务可能超过预算并产生钱包负余额。已结算消费达到成员预算或团队余额非正后，后续付费请求被拒绝。报价为费用预估，不构成可用资金预占。供应商用量缺失或不确定时保留待核对；取消和超时不代表免费。历史任务引擎保留已保存的结算语义。

接纳记录固定成员、账号、月份、时区及部门 ID。初始预算时区为 Asia/Shanghai；时区调整从下一个完整月开始。跨月结算回记接纳月份。Owner 消费持续记录，失去 Owner 身份后仍参与预算判断。月度账单区分已结算费用、待核对请求数、媒体预估，以及按入账月份统计的退款和调整。多部门成员的部门金额可能重叠；团队总额只计算一次调用。团队账单、钱包余额、资金操作及全团队账本要求 `billing.read`；个人读取不能选择其他账号，也不展示团队余额。文字核对要求供应商凭证，收费时要求完整用量。CSV 导出读取所有服务端账本分页。

<a id="storage-and-result-recovery"></a>
## 存储与结果恢复

团队总量包含个人工作区和团队空间。个人上限仅约束该成员的个人工作区，Owner 同样受限。所有保留版本和回收站对象均占用容量。有效或尚未清理的上传预占减少可用空间。分享不增加字节；复制增加。同团队移动重新检查目标归属及个人容量，并要求明确确认分享。直接跨团队移动被拒绝。

上传创建持有团队锁并预占容量。提交检查当前授权、预期元数据及接纳时的基础版本。临时上传键复制到独立的不可变版本键；延迟签名上传不能覆盖已发布版本。失败、取消及过期上传保留预占，直到持久化清理确认删除。可配置的临时对象扫描清除原签名期后的延迟写入。永久删除创建持久化任务；物理对象删除成功后才释放容量。清理重试按上次尝试排序，失败对象不能无限阻塞其他任务。资源政策未配置时拒绝新增保留字节。缩容保留数据，阻止新增占用，仍允许授权读取和清理。

媒体临时结果占用平台基础设施存储。保存到工作区执行团队容量检查，并使用幂等导入 ID。执行、结算和保存相互独立。桌面提供取消、期限内临时下载、保存重试及工作区导入；重试保留生成与计费身份。临时保留期限可配置，默认七天。恢复显示实际截止时间；保留结果不可用时明确失败，单独的供应商 URL 不保证恢复。

存储恢复显示版本、回收站及上传明细，提供分页回收站和离职交接管理。交接授予元数据管理与显式清理，不授予下载或分享权。来源成员必须停用，目标必须有效。文件复制与移动使用显式目标空间／文件夹选择器。

<a id="lifecycle-and-deployment"></a>
## 生命周期与部署

停用成员和暂停团队阻止新增工作，并请求取消未完成媒体任务。已提交任务使用后台权限继续查询供应商、结算和保存结果。成员恢复沿用原关系、预算历史和资产。退出记录移除状态并停止本地团队运行时。恢复、扩容及补款不会重放失败的付费任务。

关闭团队要求明确核对任务、资金、资产及导出。关闭保留余额、账单和数据；退款与调整由平台人工操作并填写原因。永久文件清理独立且显式。自动删除默认关闭。暂停或关闭后，授权管理人员仍可提出团队恢复申请。套餐到期阻止新增执行，同时保留授权历史读取和清理。席位和容量缩减限制新增，不删除历史；平台开通成员与邀请、恢复共用席位检查。

通过只追加的迁移日志应用包括 [0040](../../apps/api/migrations/0040_team_governance.sql) 在内的变更，不清空数据库。协调 API／客户端升级期间停止接纳新请求，保留已接纳任务处理，检查开通条件后重新开放。故障向前修复。已发布 Session 代际不变。开发数据库重建必须显式执行，应用启动不执行清库。

迁移 [0041](../../apps/api/migrations/0041_subscription_catalog.sql)导入已有套餐代码，并使用保留用量的时间戳按 Asia/Shanghai 补齐缺失计费归属。历史部门列表保留为空，因为当前归属不能证明过去成员关系。迁移保留用量行和钱包余额，不通过覆盖方式合并财务记录。

## 验证

[治理 HTTP 回归](../../apps/api/tests/team-governance.test.ts)使用独立真实 PostgreSQL、动态端口、可控时钟及接纳屏障，覆盖超额、不可变月份、有效拒绝、最后 Owner、邀请投递、容量竞争、清理重试、交接／内容隔离和目录回滚。[模型任务回归](../../apps/api/tests/model-platform.test.ts)覆盖 Worker 认领、供应商结果不明及独立结算／保存恢复。桌面单元、Host 测试及[浏览器流程](../../apps/web/tests/enterprise-settings.e2e.ts)使用明确的无密钥 fixture。[当前 SDK Session 场景](../../snapshots/session/team-settlement-sdk/snapshot.yml)记录实际用量计费与恢复；历史 SDK 场景保留旧任务计费。

真实供应商调用及真实服务／模型浏览器 GIF 需要部署凭据；缺少凭据时这些项目仍未经验证。无密钥 fixture 不代表供应商价格、投递可用性或生产就绪。
