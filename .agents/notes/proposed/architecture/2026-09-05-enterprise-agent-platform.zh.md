# Agent Note: 企业客户端运行时与云控制平面

Status: proposed

[English](2026-09-05-enterprise-agent-platform.md) | 中文

## 问题

DeepSeek Harness 是可配置的本地 agent harness（智能体框架），而不是企业服务。当前组合可以运行功能完整的 agent、持久化会话、提供浏览器 UI，并添加动态 Cordis 包，但这些机制没有定义组织、账号身份、租户授权、集中治理的模型凭据、持久化插件版本、商业计量，也不能为不可信插件代码提供安全边界。

把完整运行时迁入共享服务端可以简化治理，但也会把本地文件、Git、Shell、原生应用和客户上下文带离拥有它们的设备。把所有内容留在用户设备上可以保留这些能力，并让 agent 负责定时和长时间自动化，但云端仍需提供受治理的模型访问、短时插件调用、企业审计、成本控制和插件分发。在添加单项能力前，平台需要明确分配执行、策略和数据权威。

云端插件还带来独立的信任问题。当前动态包 Runner 在单个进程内提供有用的不可变版本和 Cordis 生命周期语义，但其 `node:vm` 上下文不是安全边界，注册表也不持久化且不可分布式运行。企业插件市场不能把该机制视为租户隔离手段，不能在实时 Worker 中安装依赖，也不能让已审核的工具 schema 偏离真正接收调用的代码。

## 提案

平台将采用以客户端 agent 执行为主、共享云控制平面治理的架构。Browser Runtime 承载浏览器安全的 agent 工作和自动化，Desktop Runtime 承载本地和原生能力，以及需要跨越单次回合的自动化，Cloud Plugin Service 提供短时按需插件调用和能力代理。云端服务不负责调度、agent loop 或长时间工作流状态。每个位置只运行该运行时和租户策略允许的工具。

控制平面负责账号与组织身份、授权、运行时注册、策略、模型路由、插件发布、审批、配额、计量、计费和审计。数据平面是企业会话事件和平台记录的权威来源。SaaS 在供应商运营的服务中隔离租户；私有化发行版在客户环境中部署相同的逻辑协议和发布制品。企业内测采用在线优先模式，不定义离线修改协调。

平台管理的模型凭据只保存在模型网关内。浏览器和桌面运行时通过网关发送受治理请求并接收流式结果。客户自带的提供商凭据作为租户 Secret 在网关处绑定，不会作为值返回给客户端。

### 桌面凭据与生命周期约束

[桌面认证客户端](../../../../apps/electrobun/src/desktop-auth.ts) 交换一次性 PKCE 授权码，并通过原生 Security.framework 辅助程序持久化得到的 Runtime 凭据。凭据字节使用私有 stdio，而不是 `security -w` 命令行参数；进程列表不能成为凭据传播渠道。回调服务绑定操作系统分配的回环端口，校验 state 与 Host，拒绝重放，并在完成或取消时关闭。在受管 Provider 缺失时，应用不启动不受约束的个人 profile。这明确放弃立即执行本地 Agent，而不是宣称独立 home 已经实现企业模型或插件策略。

[进程管理器](../../../../apps/electrobun/src/runtime.ts) 拥有 POSIX 进程组，排除继承的 Secret，并在 TERM/KILL 升级后等待 close。发出信号不代表进程已经退出。Keychain、回调、构建后 profile、LaunchAgent 主机以及 API 数据库测试覆盖开发生命周期；交互式 GUI 登录仍需要配置真实身份提供方，远程 Provider 接入属于后续平台阶段。可分发 Runtime、安装包、签名和公证明确延期到六个产品阶段之后的最终发布阶段，不是企业内测集成的前置条件。[网关](../../../../apps/api/src/gateway.ts) 在通过 PostgreSQL 事务锁串行处理幂等键之前验证设备；重复响应只返回该设备已有调用的 ID 与状态，不再发起上游请求，也不重放已完成的流。

[`EnterpriseRuntimeController`](../../../../apps/electrobun/src/runtime-controller.ts) 将本地进程管理器与可选登录启动注册绑定为一个生命周期。它先启动组织专属进程，再安装 LaunchAgent；登录启动时写入组织专属 `DSH_HOME`，注册失败时回滚进程，并且只移除自己安装的 agent。[DesktopSession](../../../../apps/electrobun/src/desktop-session.ts) 从 Keychain 读取已认证凭据，启动该控制器，续租 Runtime，在租约失效后停止本地工作，在组织切换时避免进程重叠，并在退出登录时删除凭据。内置可执行文件和完整 Web profile 仍需通过桌面安装冒烟测试。

### 原生模型传输

[企业适配器](../../../../apps/electrobun/src/gateway-provider.ts) 实现原生 LLM 接口，不向客户端暴露上游密钥，也不重写 Agent Loop 请求。它只公布服务端授权目录，检查 Keychain 凭据与 origin／设备的绑定，续期设备租约，并在不修改模型可见消息的前提下映射辅助用途。文本和工具流使用共享且经过校验的网关记录。提供方禁用自动重试：计量结果不确定时，不能安全地推断新模型请求免费。代价是缺少自动恢复，以及首期图片／推理控制支持，这些仍是明确的交付缺口。

网关在转发完成标记前校验流并计量。真实 PostgreSQL 测试验证重叠预留、实际结算、陈旧策略拒绝和截断流保留预留；构建后的命名 profile 冒烟测试验证原生加载与 Keychain 访问。生成的桌面 profile 会将此提供方与远程 SessionPersistence、原 Web 用户界面和企业账户桥接组合。自动成本核对、录制 Agent Session 覆盖以及已批准插件激活仍是独立的交付缺口。

### 插件执行与发布

一个插件身份可以为 `browser`、`desktop` 和 `cloud` 发布不可变目标制品。每个版本都把工具 schema、制品、依赖锁文件、权限、资源限制、可靠性声明和商业策略绑定到已审核的摘要。任何相关变化都会创建新版本，并使替代版本无法继承先前审批。

开发者提交源码和锁文件。由平台控制的构建器通过获批 npm 和 PyPI 代理解析依赖、扫描源码和依赖闭包、运行声明的检查、创建 SBOM，并签署不可变的 Node.js 或 Python 制品。AI 审核器生成可解释的发现结果和风险分类；企业人类审核者批准或拒绝精确的制品和权限摘要。运行时沙箱以只读方式挂载代码，并且不安装依赖。发布者提供的任意 OCI 镜像不属于企业内测范围。

每个云端插件版本都通过项目现有的统一沙箱适配器执行。服务可以为短时调用保留少量热实例池，但不拥有自动化状态或长时间工作。部署过程预加载并健康检查候选版本、路由有限灰度流量、以原子方式把新调用发送到获批版本，然后释放空闲容量。每个实例默认只接受一个并发调用；经审核的可重入声明可以允许更高并发。

云端插件调用采用至少一次投递，并包含稳定的 `callId`、幂等键、期限、尝试次数和版本摘要。自动重试必须具有获批的幂等分类。对象存储、插件 KV/SQL、企业数据库连接、Secret、网络出口、队列和可观测性都通过代理提供，并在沙箱外按默认拒绝策略强制执行。

### 商业职责分配

SaaS 采用组织订阅、活跃席位、模型与云资源计量用量的组合。积分用于展示预算和消费，但不取代资源与币种账本。私有化部署采用年度平台许可和支持计划，同时保留内部用量分配。企业私有插件先于公共市场交付；公共插件需要平台审核和企业审批，商业权益与可执行权限保持分离。

完整产品、架构、协议主题、交付门槛和单位经济模型位于[企业平台蓝图](../../../../docs/developer/discussion/enterprise-agent-platform.zh.md)。本 Agent Note 只负责跨系统职责分配及其理由。

### 与现有决策的关系

本提案扩展但不取代[浏览器动态包提案](2026-08-08-cordis-web-dynamic-packages.zh.md)。该提案负责 DSH 进程内的临时 Host/Client 包、审批和生命周期；本提案要求进程外持久化且受租户约束的发布与路由服务。

本提案还保留[自指 Cordis 工具包](../../implemented/feature/2026-07-08-self-referential-cordis-toolset.zh.md)作为可信本地开发机制，并保留 [WebWorker 预览](../../implemented/architecture/2026-08-20-webworker-pack-lowering-and-preview.zh.md)作为浏览器兼容性证据。这两个决策都不承诺企业安全边界。它们的现行理由仍各自有用，因此本提案不会取代或归档任何现有 Agent Note。

## 考虑过的替代方案

**让每个 agent 都在服务端运行。** 这种方案为服务端提供单一执行和持久化模型，但会迫使本地文件、仓库、Shell 和原生集成通过远程上传或高权限连接器访问。它会削弱本地 harness 的主要价值，并增加平台处理的敏感客户数据量。

**让所有执行都留在设备上，服务端只负责账号和计费。** 纯设备执行无法提供受治理的短时插件调用、集中版本撤销、共享能力代理、持久化企业审计或一致成本控制，并且会让每个外部集成都依赖设备可达性。

**把云端插件作为 Cordis fiber 运行在共享 Worker 进程内。** Cordis 资源释放可以处理生命周期清理，但不能隔离恶意代码，不能限制 CPU 或内存，不能分隔租户文件系统，也不能实现故障独立。共享进程会让一个插件崩溃或阻塞无关租户。

**在云端调用启动时安装依赖。** 实时安装会让延迟和执行代码依赖可变注册表，在运行时保留包管理器凭据，并破坏已审核源码与制品之间的联系。隔离构建和不可变制品使实际执行字节可审计且可复用。

**从首个版本开始允许发布者提供任意 OCI 镜像。** 任意镜像支持更多语言，但会大幅增加供应链审核、内核攻击面、私有化兼容性和运维差异。锁定版本的平台 Node.js 与 Python 镜像能够以有限策略范围覆盖预期内测工作负载。

**先发布 SaaS，之后再设计私有化部署。** 这条路径可以减少初期运维，但可能把供应商基础设施和身份假设嵌入所有协议。让两种发行版遵循同一个一致性目标会提高初始成本，却能保持企业数据与部署模型的可信度。

## 验收条件

- 浏览器和受管桌面运行时可以使用不透明租户与操作者身份完成注册，获取获准工具视图，使用模型网关，并向企业权威存储追加可重建的会话事件。
- SaaS 和私有化发行版针对身份、策略、运行时租约、会话持久化、审计、计量、插件版本验证和撤销通过同一套协议一致性测试。
- 开发者可以提交一个锁定 Node.js 或 Python 依赖的企业私有插件，平台无需重启控制平面即可构建、扫描、审核、签名、灰度、激活、回滚和撤销其不可变版本。
- 云端插件只能通过获批代理操作访问存储、数据库、Secret、网络或队列，每个允许或拒绝的操作都可以归属到租户、操作者、插件版本和调用。
- 停滞、崩溃、超预算或被撤销的插件实例不能把新调用路由到另一个租户或未获批版本，其故障也不会停止其他插件版本的实例池。
- 模型和插件用量可以与幂等的资源及币种账本核对；组织、团队、用户、模型和插件预算可以在接纳新成本前发出警告或拒绝。
- 企业管理员可以重现一项请求的身份、策略修订、版本摘要、能力决策、会话结算、用量和结果，同时不会收到无关租户内容。
- 公共市场阶段交付后，公共插件执行不能绕过平台审核、企业审批、购买权益、摘要固定或紧急撤销。

## 风险

- 同时支持 SaaS 与私有化部署会提高发布、支持、升级和可观测性成本。共享协议、制品和一致性测试必须防止它们演变为两个产品。
- 浏览器 agent 无法提供与桌面进程相同的原生能力。能力发现和激活必须在模型依赖不可用工具前失败。
- 集中式会话权威可以改善审计与恢复，但会增加隐私、地域、泄露和保留义务。租户策略和私有数据平面部署必须属于第一版架构，而不是后续 UI 设置。
- 即使采用微虚拟机或容器隔离，隔离不可信 Node.js 和 Python 代码仍是高风险安全工作。外部能力强制、资源控制、补丁、事件响应和快速撤销都是持续运维要求。
- 至少一次投递会让具有非幂等副作用的插件面临不确定结果。平台必须拒绝盲目重试，并让人工恢复清晰可见。
- 当供应商价格或插件资源特征变化时，席位与用量定价可能掩盖负毛利。账本必须保留原始计量值和供应商成本，使商业策略可以改变而无需重写历史。
- 在线优先策略使控制平面可用性成为用户体验的一部分。内测版本放弃离线策略敏感执行，以避免过期授权和冲突语义。

## 用户端模型选择

企业客户端保留原 Web 设置壳，但用企业自有的“模型”页面替代个人模型编辑器。页面通过受信任的 Host RPC 读取授权目录和当前 `enterprise` 选择，只能通过本地默认模型服务写入目录中的模型，最终授权仍由网关在每次调用时执行。这样用户可以保持熟悉的视觉界面，同时不会接触上游地址、凭据或未经治理的 Provider 选择。
