# Agent Note: 保持企业浏览器来源与模型容量一致

Status: implemented
Archived: 2026-09-14

[English](2026-09-14-enterprise-browser-origin-and-model-capacity-validation.md) | 中文

## 问题

企业控制台与 API 是分离的回环来源。开发者可以用 `localhost` 打开控制台，而配置使用 `127.0.0.1`；浏览器会因此阻止带凭据的请求，尽管两个名称都指向本机服务。模型编辑器还接受了 API 会拒绝的容量：384000 的输出上限对已支持的模型目录是有效值，却超过 API 原本 131072 的管理上限，最终产生含义不清的 400 响应。

## 决策

API 从配置的管理端与门户来源生成带凭据的浏览器允许列表。它保留配置来源、将其规范化为 URL origin，并且只对回环主机加入 `localhost`/`127.0.0.1` 的对应名称。Hono CORS、可变更请求来源检查和 Better Auth 的受信来源共同使用这份列表。公共部署来源不会被扩展。

平台模型目录接受最高 2,000,000 token 的上下文与输出容量，与现有上下文上限以及声明 384,000 输出 token 的模型保持一致。管理控制台的表单对容量数字字段采用同一上限，使超大值在提交前得到拒绝。

生成的本地企业环境会明确允许 `https://api.deepseek.com`，部署可以通过 `ENTERPRISE_MODEL_ORIGINS` 添加其他 HTTPS 来源。服务端对每个保存模型仍强制执行来源检查。

## 备选方案

**要求开发者严格使用配置中的主机名。** 不予采用，因为交付的开发命令绑定 `127.0.0.1`，而浏览器和书签通常使用 `localhost`；这两个回环别名之间的差异是意外的，对安全没有额外收益。

**允许全部来源或反射请求的 Origin。** 不予采用，因为带凭据的 CORS 会变成宽泛的跨站登录入口；部署来源必须保持显式允许列表。

**保留 131072 token 上限并拒绝 384000。** 不予采用，因为 harness 已经能发现声明 384000 输出 token 的模型，平台目录的目标是表示任意配置的 OpenAI 兼容路由。

**只提高服务端上限，不限制表单。** 不予采用，因为浏览器应即时反馈，并且其接受范围应与服务端约定保持一致。

**默认允许所有上游来源。** 不予采用，因为模型网关会发出带凭据的出站请求；本地便利默认值仅限官方 DeepSeek 来源，其他提供方仍需部署显式选择。

## 影响

无论使用哪个受支持的主机名，回环管理端和门户会话都能工作；非回环来源仍由配置明确允许。容量不超过 2,000,000 token 的模型保存请求通过 schema 校验；请求计费仍会将每次调用限制在已保存的模型上限内。界面上限只是客户端便利措施，API 对非浏览器调用仍是权威校验方。
本地初始化器提供官方 DeepSeek 来源，因此全新的开发栈可以保存控制台中显示的端点，同时不会削弱部署允许列表。

## 测试

`apps/api/tests/config.test.ts` 覆盖回环别名、URL origin 规范化，以及公共来源不添加别名。API 与管理端 TypeScript 检查覆盖共享来源接线和模型容量变更。
