# Agent Note: 团队资源接纳与保留恢复

Status: implemented

[English](2026-10-23-team-resource-admission-and-recovery.md) | 中文

## 问题

层级继承可能授予其他团队数据的权限，平台恢复也可能误用成员身份。媒体预占及部分超额收款与文字结算后扣款冲突。仅统计有效文件当前版本，会使保留版本、回收站及并发上传突破容量，且缺少可解释的记录。

## 决定

两种部署模式下，每支团队均要求精确成员关系。部门组织团队内部人员与分享，不隐含团队管理权。平台身份通过独立、填写原因且留审计的操作工作，不授予内容访问权。有效团队权限扣除显式拒绝，交互管理、目录同步及生命周期操作共用最后有效 Owner 保护。选择团队先停止旧桌面运行时，失败不回退到另一团队。

付费接纳检查团队正余额及发起成员的月度已结算消费。当前媒体与文字在结算后完整扣除实际费用；已接纳请求可能同时超出两种限制。Owner 仅豁免个人预算。接纳固定账号、成员、预算月份、时区及部门 ID。角色变更及恢复保留消费。供应商用量不明时保留待核对。历史任务引擎保留持久化计费语义。

团队容量计算保留版本、回收站及上传预占。接纳通过团队记录串行化。发布将临时对象复制到独立不可变版本键；持久化物理清理仅在删除成功后释放占用。同团队移动重新检查目标归属和分享；复制增加占用。离职交接授予管理元数据，不授予内容访问。停用后，已提交任务保留受限后台权限以查询、结算和保存；保存重试保留原生成及计费身份。

[团队管理](../../../../docs/developer/enterprise-team-governance.zh.md)负责操作细节。本决定取代[团队隔离](../bug-fix/2026-10-22-open-registration-team-isolation.zh.md)中的私有公司继承，以及[平台目录](2026-09-14-platform-wide-model-catalog.zh.md)中的全团队可见性。原记录保留显式查询／RLS 和单一发布来源的有效理由。[身份提案](../../proposed/architecture/2026-09-05-enterprise-identity-and-organization.zh.md)保留独立未完成范围。

## 考虑过的替代方案

**媒体预占或仅收取可用余额。** 前者使并发工作按不同于文字的规则被拒绝，后者遗失部分供应商实际费用。预估仅供参考；完整扣款保留财务历史。

**用子团队表达私有公司部门。** 祖先成员和角色使独立承担费用的团队共享权限。团队内部门保留组织结构，同时不授予跨团队访问。

**向平台操作人员或资产交接人授予成员／内容权限。** 恢复只需要选定对象的有限修改和原因；隐含内容权超出用途。读取仍要求明确分享。

**逻辑删除时释放容量或仅计算当前版本。** 保留对象继续占用容量，物理删除失败可能长期存在。持久化删除确认使计量对应自有字节。

## 后果

资源政策和配置版本必须显式表达；过期修改被拒绝。缩容保留数据。在途调用可能造成钱包负余额或成员超额，此后停止新增付费接纳。暂停、关闭、补款及恢复保留账单和资产，不重放失败付费任务。迁移 0040 只追加；应用启动不重建数据库或改写已发布 Session 代际。

## 验证

独立 PostgreSQL HTTP 测试覆盖精确成员、拒绝、Owner 保护、并发接纳、月份归属、不可变上传提交、持久清理、交接及目录补偿。桌面 Host／Client 测试及无密钥浏览器／Session 场景验证共享 SDK 和账号流程。真实供应商执行、生产邮件投递及真实服务／模型 GIF 需要部署凭据；fixture 不能证明这些结果。
