# Agent Note：Admin 发布签名客户端安装包

Status: implemented

[English](2026-10-21-admin-desktop-release-publication.md) | 中文

## 问题

平台管理员需要通过企业 API 发布大型客户端安装包，同时不能让 Web 控制台或制品存储拥有签署可执行版本的权限。

## 决策

[Admin 版本页面](../../../../apps/admin/app/desktop-releases-workspace.tsx) 接收安装包及离线签名文件。[API 发布器](../../../../apps/api/src/desktop-releases.ts) 与原生更新器使用同一个 [Ed25519 协议解析器](../../../../apps/api/src/desktop-release.ts)。部署固定公钥；私钥保存在仓库、浏览器、API 和构建输入之外。签名下载地址精确指定部署 API、目标平台和语义版本。

API 在读取安装包流之前验证平台管理员身份。它按签名大小限制字节数，写入私有临时文件，验证 SHA-256，再上传到新的私有 MinIO 对象键。数据库事务按目标平台串行发布，重新检查管理员权限，拒绝相同或更低的语义版本。已发布记录不可覆盖。匿名只读接口提供最高已发布版本，并流式返回不可变安装包；草稿不可公开访问。更新地址按语义版本而非时间戳选择版本。204 表示尚未发布版本，绝不授权安装。

上传失败或取消时，系统删除临时文件，并在确定回滚时删除未提交对象。若数据库提交响应丢失，系统保留对象，因为发布可能已经持久化。此类无引用对象由存储维护清理。浏览器取消可能与已提交的发布竞争；管理员重试前应刷新列表。入口代理限制和临时磁盘容量必须支持每个并发上传。

[签名客户端更新决策](2026-10-20-signed-desktop-updates.zh.md) 继续负责初始信任、公钥轮换、用户确认、取消和原生安装器交接。本文负责 API 发布，并保留上述独立的安全决策依据。[API 部署设置](../../../../apps/api/README.zh.md#desktop-releases) 负责运行配置。

## 考虑过的替代方案

**在 API 或浏览器签名。** 离线签名可防止已被攻陷的管理会话或制品存储生成已安装客户端会接受的版本。

**缓冲整个安装包。** 通过有界临时文件流式处理，避免分配安装包大小的缓冲区，并在持久发布前完成精确验证。预签名上传需要外部可访问的存储和浏览器 CORS 配置；API 流式上传使用部署已有的私有存储地址。

## 影响

发布密钥必须保留供后续构建使用，每个目标平台需要独立更新地址。初始安装需要带固定更新配置的可信安装包。macOS 更新仍然打开已验证 DMG，由用户明确替换应用；Apple 签名与公证仍是独立流程。

独立 PostgreSQL 验收覆盖权限、签名拒绝、大小与哈希失败、不可变下载、存储失败、并发发布及回滚清理。原生更新器测试覆盖空更新地址和已认证安装包交接；Admin 请求测试验证 File 上传、取消和签名大小检查。发布结果固定在所有者本地预期文件中，因为此控制面操作没有 Session 转录。 本地浏览器验证也通过真实 API 和 MinIO 发布签名安装包，并从公开安装包接口下载匹配的字节。
