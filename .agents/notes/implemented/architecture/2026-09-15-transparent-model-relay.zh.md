# Agent Note：企业模型透明中转

Status：implemented

[English](2026-09-15-transparent-model-relay.md) | 中文

## 问题

企业模型路由会重新组装一个字段很少的 chat-completions 请求和响应，导致提供方扩展字段丢失，也无法选择其他兼容的上游路径。

## 决策

原生 DSH 适配器会请求流式 token 用量，并校验它实际消费的流。模型路由验证桌面 Runtime 并解析平台启用的模型，然后转发调用方指定的路径、方法、JSON 请求体、请求头和响应字节。它只把请求体中的 `model` 替换为配置的上游模型，并把 `Authorization` 替换为加密保存的平台凭据。模型授权、策略修订号、预算准入、限流和响应重构不属于这条中转路径。路由会在发送前以原子方式占用组织与请求幂等键；重复请求会收到冲突响应，不会再次调用上游。有界旁路观察器会检查成功的 OpenAI 兼容 SSE，但不会消费、存储或修改响应字节。最后一条合法用量事件后出现 `[DONE]` 时，系统会先结算占用，再转发完成标记。[人民币用量分析](../feature/2026-09-16-cny-model-usage-analytics.zh.md)定义已保存 token 和成本的语义。不完整、非法、超限、非 SSE 和非 2xx 响应会释放占用，不会生成用量记录。结算存储失败会保留待人工核对的占用，同时不改变模型响应。HTTPS 传输会为每次连接尝试解析全部 IPv4 应答；只要集合中存在非法或内网地址就拒绝整个集合，并根据 Node 的要求返回单地址或地址数组回调形式。请求失败、响应流失败、上游错误状态和计量失败只记录非敏感的请求标识及相应的错误分类；请求建立失败会返回通用 502。

## 备选方案

**保留网关自有的 OpenAI 请求组装。** 不采用，因为固定字段列表和端点后缀无法承载提供方扩展或其他兼容 API。

**把上游凭据转发到桌面端。** 不采用，因为平台凭据必须留在 API 进程中，Keychain 凭据只用于标识桌面 Runtime。

**在 API 中解析并重建上游 SSE。** 不采用，因为协议相关解析会改变响应，使非 chat 兼容的上游不可用。

**把计量完全放在中转之外。** 不采用，因为 API 已经拥有已认证的组织、Runtime、模型价格和原样响应流，可以在不控制请求准入的前提下记录完整的 OpenAI 兼容用量。

## 影响

兼容的提供方可以直接收到自己的请求选项和路径，无需修改 API。完整的 OpenAI 兼容流会写入现有用量视图，其他提供方和路径仍可使用，但不接受平台计量。计量是响应后的观察，而不是准入控制：预算值不会阻止调用，也不会创建预留。Runtime 认证以及公网 HTTPS/DNS 安全校验仍然保留。

## 测试

API 和 Electrobun 包的 TypeScript 检查通过。聚焦传输测试覆盖 Node 的两种 DNS 回调形式、空集合与不安全应答集合、脱敏诊断、分片用量事件、非法 UTF-8、格式错误与超限流，以及缺少完成标记。PostgreSQL 集成测试使原生调用重叠，验证预算耗尽时仍会生成 settled token 和费用记录、截断调用不留记录，并证明并发的重复幂等键不会发送或记录第二次调用。原生网关套件在新的中转请求封装下通过，并继续由客户端适配器校验 DSH chat 流。通过生产 HTTPS 与 DNS 传输发出的流式与非流式手动请求均已从平台启用的 DeepSeek 模型收到成功的结构化响应。
