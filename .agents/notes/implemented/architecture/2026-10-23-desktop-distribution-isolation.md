# Agent Note: Desktop distribution identity isolation

Status: implemented

English | [中文](2026-10-23-desktop-distribution-isolation.zh.md)

## Problem

An additional desktop product must not redirect enterprise builds, reuse installed enterprise data or become an accepted enterprise update. Shared build processes can inherit another product's selector and service configuration.

## Decision

The [distribution configuration](../../../../apps/electrobun/src/distribution/config.ts) validates immutable Zhiyu and Arivo identities, product-owned version selection, platform data roots and separate build/output directories. Enterprise brand and data-path consumers explicitly select Zhiyu. The root enterprise desktop build and package commands use a [child-process wrapper](../../../../apps/electrobun/scripts/run-distribution.ts) that pins Zhiyu and removes Arivo configuration without mutating the parent environment.

Native credential helpers pin the product through compiler options. Arivo neither migrates enterprise Keychain services nor writes enterprise DPAPI directories. Default compilation retains Zhiyu migration and paths. [Background service declarations](../../../../apps/electrobun/src/launch-agent.ts) select the label and plist path from an explicit product and default to the enterprise identity.

The [bundled loader](../../../../apps/electrobun/src/distribution/bundled-plugin.ts) checks a pinned digest, protocol version, release version, platform, inventory and all file hashes before activation. Its caller must supply the digest from signed application configuration and keep installed resources immutable while loaded; a user workspace or marketplace lease cannot supply trust. Verification failure, cancellation or a missing declared file prevents registration. Concurrent shutdown shares one asynchronous disposal result.

The enterprise build configuration refuses any other distribution rather than applying Arivo presentation to an enterprise account composition. The [Arivo native entry](../../../../apps/electrobun/src/distribution/arivo-index.ts) starts only a verified first-party Host/Client/Agent artifact through a DSH profile. Its build/package/verify commands consume an explicit release directory, separate product staging and the CLI production closure. The local macOS DMG verifier uses a read-only mount and temporary installed copy; ad-hoc signing does not establish formal release trust. Arivo does not compose the enterprise updater or an active update feed.

Electrobun 2.0.1 requires the install root to exist before its native manager registers a first macOS launch. The Arivo-only [bootstrap](../../../../apps/electrobun/native/arivo-bootstrap.c) creates that product directory through checked directory handles, then replaces itself with the unmodified bundled launcher. It preserves the process ID, arguments and termination behavior; redirected or unsafe directory components fail before delegation. No SDK or enterprise launcher modification is required.

The [branding decision](2026-10-21-zhiyu-desktop-brand.md), [enterprise credential decision](2026-10-23-enterprise-upgrade-and-administration.md) and [signed update decision](2026-10-20-signed-desktop-updates.md) retain their existing enterprise identity and compatibility requirements. No enterprise Admin, API schema, update protocol, trust key or image publication entry is changed.

The plugin Host owns a kernel file lock through the bundled native helper; closing the Host releases it without deleting lock files or guessing PID ownership. Each launch writes its own profile directory, so a rejected second instance cannot replace the running profile. The Host monitors the native owner, and the supervisor awaits process shutdown before removing its profile. The workbench reports local runtime readiness; the independently versioned plugin owns account and creative use cases.

The [Arivo account settings](../../../../apps/electrobun/src/distribution/arivo-identity.ts) accept explicit Web/API origins and bounded timeouts. The builder embeds those settings in the Arivo main process; the supervisor supplies only non-secret values and its compiled Arivo credential helper to the first-party Host. Omission preserves offline startup without enterprise authentication. The independent plugin consumes the versioned Arivo Identity wire protocol and owns tokens outside the browser and business database. Real-account and native browser acceptance remain separate from configuration and helper verification.

The Arivo profile composes the original OS base and Web application bundles before loading its verified creative plugin. Its startup adapter contributes an authenticated RPC, a rail entry and a namespaced `main.surface` page; the native window opens the original conversation. The creative page runs in a frame restricted to the owning OS origin, preserving the original Session provider and isolating creative CSS. The pane lifecycle marks its owning document while mounted; the startup theme pins that active creative page to the permanent 56px rail and a flexible center, with no session-sidebar or workbench reservation; conversation layout retains its own columns. Lifecycle-owned Arivo token overrides style the entire OS and its portal dialogs in both appearance modes. The sidebar owns an optional selected-navigation fill token, with the released blue fallback unchanged when no product overrides it. Rail entries and Settings sections request versioned page, locale and color-scheme fields through the authenticated RPC; unknown or duplicate query fields are rejected before document rendering. The Host index transform supplies the Arivo document title, boot wordmark and verified favicon before Client plugins activate. An optional mount-point data attribute names the static boot page, preserving the default wordmark for other products. The builder compiles Client artifacts and the frontend before staging the runtime. The account entry uses the creative Host’s existing native identity, without exposing credentials to either browser. Arivo omits the DeepSeek credential onboarding row without changing enterprise composition. This composition retains OS tools, presets, subagents, Skills/MCP and settings. Arivo marketplace services remain an independent acceptance requirement.

The supervisor resolves native identity before starting any user Agent, using a disposable profile that contains only the verified creative plugin. The Host emits `arivo account-scope: v1:<device-or-digest>` after loading or durably changing native credentials; tokens and browser-provided scopes are absent. A confirmed user selects a checked private `accounts/<digest>/agent` DSH home, while device use retains its existing directory. The entire process, including Session stores, search caches, workspace registry, preset roots, settings and permissions, is replaced after an owner change. The native view is cleared before shutdown and navigated only after the replacement confirms its scope. This prevents old in-memory projections and background tasks surviving an account switch. Interrupted refresh retains the local owner; durable sign-out switches to device scope even when remote revocation is unavailable. Existing device records are not moved into an account. [Scope tests](../../../../apps/electrobun/tests/arivo-account-scope.test.ts) reject path traversal, links and unsafe directory modes; built-profile regressions cover two account homes, offline sign-out, old-URL expiry, settings/preset separation and restoring committed Sessions. Real cloud identity and native/Windows acceptance remain separate requirements.

## Alternatives considered

**Select branding from an ambient environment variable at runtime.** A launched enterprise application could adopt another product's paths or identity. Released enterprise consumers select their product explicitly.

**Copy the enterprise desktop into a second app.** This duplicates lifecycle and security ownership before the separate Arivo composition exists.

## Consequences

[Distribution regressions](../../../../apps/electrobun/tests/distribution.test.ts) pin released enterprise values, independent Arivo version/data identities, immutable configuration, child-environment isolation, rejected composition selection and rejection of a correctly signed Arivo update by the enterprise updater. The metadata does not migrate installed data or credentials. Enterprise Admin and API remain independent of the Arivo plugin checkout and assets.

[Native credential regressions](../../../../apps/electrobun/tests/keychain.test.ts) use one fresh test account key to verify both compiled helpers cannot read, overwrite or delete the other product's values. [Bundled regressions](../../../../apps/electrobun/tests/bundled-plugin.test.ts) load a real local ESM entry and check tampering, paths, missing files, budgets and disposal errors. Windows requires native execution; macOS results do not substitute for it. [Production-image regressions](../../../../apps/electrobun/tests/enterprise-images.test.ts) opt in through `DSH_ENTERPRISE_TEST_API_IMAGE` and `DSH_ENTERPRISE_TEST_ADMIN_IMAGE`, own a private database, object store and network, and verify initialization, login, restart idempotence and Admin standalone startup without changing existing service data.
