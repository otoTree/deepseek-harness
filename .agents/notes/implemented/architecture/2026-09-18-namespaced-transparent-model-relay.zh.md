# Agent Note: 带 namespace 的企业模型透明中转

Status: implemented

[English](2026-09-18-namespaced-transparent-model-relay.md) | 中文

## 问题

企业网关必须保留提供方协议路径和扩展字段，不能把每个 OpenAI 兼容操作都变成平台业务端点。但 terminal catch-all 中转会把控制面路由中的每个未命中请求都变成经过认证的外发路径。接受上游模型名还会允许调用方选择平台启用目录之外的模型，绕过平台价格与用量身份。

## 决策

API 拥有一个数据面 namespace：`/model/*`。只有这条正向路由会进入中转。网关移除 `/model`，把剩余路径和查询参数追加到配置的提供方 base URL，并保留来路 method、提供方 JSON 字段、响应状态和安全响应头。网关会移除重定向、服务身份、cookie、报告及提供方 CORS 响应头。一个与协议无关的流式过滤器会替换文本响应中的提供方 origin、hostname 和上游模型名，包括跨 chunk 的字面值；二进制响应仍按原字节传输。过滤器会在替换前解码标准 HTTP 压缩，但不会重建 Chat、Responses 或 Files 记录。网关不维护端点列表，也不根据模型的协议元数据选择 URL。控制面和未知路径绝不会落入模型外发。

每个中转请求都会验证有效的 Runtime 令牌，并从令牌推导账号和组织。JSON 请求通过 `body.model` 选择已启用的平台模型 UUID；没有请求体的 Files 请求使用 `X-DSH-Model`。两者同时存在时必须一致。提供方模型名、非法标识符、未知 UUID 和已禁用模型都会在发送前失败。网关随后把 JSON 的 `model` 值替换为目录中的 `upstreamModel`，把 `Authorization` 替换为加密保存的平台凭据，并移除 host、cookie、hop-by-hop 和 `X-DSH-*` 请求头。组织与 Runtime 目录不包含提供方 base URL、上游模型名和凭据；只有平台管理员 API 会返回前两项。`X-DSH-Purpose` 只用于用量归因，不能选择上游 URL 或模型。

Runtime、组织、账号和平台模型身份还共同限定进程内提供方文件权限。仅当对应权限仍然有效时，文件状态、删除和模型输入才会接受提供方文件标识符。上传返回处理状态时，适配器会在共享上传操作内按可配置间隔轮询原生文件资源；上传超时和取消信号同时限制轮询等待与状态请求。进程重启会使权限失效，并允许适配器执行一次有界的上传和模型调用重放。提供方文件标识符绝不会进入 Session 数据、数据库记录或诊断。

原生适配器会请求 OpenAI 兼容用量并验证它实际消费的协议流。API 在发送前按组织和幂等键占用可计费请求。每个上游 chunk 都先写给调用方，再由有界旁路观察器处理。完整且合法的用量会结算占用；缺失、非法、超限或截断的用量保留为 `pending_reconciliation`；上游错误记录为 failed 占用。计量或数据库故障不能删除已经中转的字节。HTTPS 传输会拒绝含凭据的端点、字面 IP host，以及包含任何私网或非法地址的 DNS 应答集合。诊断不包含配置的端点、凭据、请求头、查询参数、请求体、媒体正文、Base64 或提供方文件标识符。

## 备选方案

**使用 namespace 之外的 terminal catch-all。** 不采用，因为新出现的控制面拼写错误或已移除路由会静默变成提供方外发。正向 namespace 无需枚举提供方操作，也能明确数据面决策。

**分别创建 Chat、Responses 和 Files 平台路由。** 不采用，因为端点专属处理程序会重新引入透明中转要消除的兼容层。提供方新增兼容路径时不应要求 API 发版。

**信任请求体模型或上游模型名。** 不采用，因为平台模型身份拥有启用状态、凭据、价格、限制、用量归因和钱包扣款。只有服务端可以把该身份映射到上游名称。

**把提供方凭据转发到桌面端。** 不采用，因为 Runtime 凭据只验证一个设备和组织，不得暴露平台持有的提供方密钥。

**在 API 中解析并重建 SSE。** 不采用，因为重建协议流可能延迟或丢失模型输出。身份脱敏只匹配精确字节，不解释协议记录；用量观察保持有界，并且发生在每次写入之后。

## 影响

桌面端和内部插件审核调用 `/model/chat/completions`、`/model/responses` 和 `/model/files`，提供方收到 `/chat/completions`、`/responses` 和 `/files`。其他提供方路径也可以在同一前缀下工作，不需要协议专属服务端路由。客户端无法把 API 路由未命中变成外发，也不能发送不同的上游模型，同时用更便宜的平台模型身份计费。固定 namespace 会出现在传输配置中，但请求和响应正文仍不包含平台 envelope。

## 测试

PostgreSQL 集成覆盖 Runtime 绑定、namespace 拒绝、任意 method／path／query 转发、提供方字段保留、平台 ID 验证、请求体／请求头不一致、启用模型解析、上游模型替换、内部请求头移除、响应头过滤、跨 chunk 身份脱敏、幂等、文件归属、SSE 完成与截断、响应交付后的结算故障和钱包扣款。传输测试覆盖公网 DNS 强制、脱敏诊断、取消、超时、非法流和有界观察。Electrobun provider 测试会发送带 namespace 的 Chat、Responses 和 Files 请求，覆盖处理到可用的轮询、失败及未知文件状态、上传超时、取消和单次上传复用，并继续验证原生提供方流。
