# Agent Note：企业 Admin 使用领域路由和持久化审批工作流

Status: implemented

[English](2026-10-01-enterprise-admin-domain-routes.md) | 中文

## Problem

参考导出将组织、同步、权限、模型、身份和平台操作分成独立工作区。现有 Admin 通过查询参数选择一个通用表格，API 也没有持久化同步决策、身份映射、登录失败或会话审批。

## Decision

Admin 使用按领域分组的可分享 App Router URL。组织目录、成员详情和账号详情使用独立路由；同步包含脚本、任务、差异和历史路由；权限包含目录、角色和会话审批路由；模型包含目录、适配器和 Runtime 详情路由；身份包含身份源、字段映射和登录失败路由；平台包含设置、兑换码和健康路由。

共享壳层负责导航和浅色工作画布。每个领域页面使用资源专用视图，明确列出列、指标和详情或审批区域。旧的 `?section=` 导航不再维护。

同步预览创建只追加的差异记录。差异决定使用版本检查。回滚创建补偿运行并保持源运行不变。身份字段映射、脱敏登录失败记录和会话审批决定都按租户隔离、检查权限、写入审计，并在可能并发决定的地方使用版本。健康接口在没有真实供应商探针时报告未知，不伪造可用率。

## Alternatives considered

- **继续扩展通用表格** —— 这会让树导航、代码审核、字段映射和审批继续共用不合适的交互模型。
- **继续把查询参数作为主导航** —— 查询参数适合筛选状态，但不能提供稳定领域 URL，也不能为详情页提供路由级 owner。
- **回滚时覆盖同步历史** —— 这会隐藏原始决定并阻碍审计重建；补偿运行保留两份事实。

## Consequences

- Admin URL 可以按领域收藏、分享和独立测试。
- API 迁移增加持久化工作流记录和租户级行级安全策略。
- 共享壳层保持较小；领域专用表单和操作入口靠近所属资源。
- 外部系统尚未提供真实健康信号时，探针状态保持可见的未知。

## Verification

Admin 类型检查、单元测试和生产构建通过。API 类型检查和聚焦 API 测试通过。领域路由由 App Router catch-all 根据显式路径解析渲染，新工作流表包含在迁移 `0033_admin_workflows` 中。
