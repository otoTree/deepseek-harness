# Agent Note: 签名桌面端完整安装包更新

Status: implemented

[English](2026-10-20-signed-desktop-updates.md) | 中文

## Problem

已安装的企业桌面端需要可验证的新版发布路径。存储被入侵时，HTTPS 下载及旁边的校验和不能独立验证发布者身份。本机安装包尚无平台发布者身份，而替换运行中的桌面端可能让其拥有的 Runtime 继续活动。

## Decision

[原生更新器](../../../../apps/electrobun/src/desktop-updates.ts) 为启动发现与用户请求的安装认证发布。[启动更新通知](2026-10-23-startup-desktop-update-notification.zh.md)负责发现时机和通知关闭；本文保留发布认证与安装器交接的决策依据。安装包构建嵌入一个 HTTPS 清单地址和一个 Ed25519 SPKI 公钥；配置不成对会失败，两者均省略时禁用更新。[发布签名器](../../../../apps/electrobun/scripts/sign-update.ts) 将私钥保留在构建输入之外，对包含应用标识、语义化版本、平台、下载地址、大小、SHA-256 和更新说明的精确载荷字节签名。客户端先认证，再解析这些字段，只接受匹配平台且语义化版本更高的发布。此信任模型要求可信的初始安装包，无法抵御签名私钥泄露或本地管理员。

下载流式写入私有临时目录中的独占、仅所有者可读写的文件。清单读取有大小上限；HTTPS 重定向不能引入 HTTP 或 URL 凭据。验证完成后才解压 Windows ZIP 或向原生安装器交接。原生菜单支持取消，并发检查共用一次交互，退出会中止并等待活动 I/O，同时使迟到的对话框结果失效。安装需要二次确认，通过已有退出守卫停止所拥有的 Runtime，打开完整安装包，然后允许原生退出。已有退出流程会拒绝额外的安装器回调。安装器启动失败会明确提示，并允许正常退出。

设置 → 通用设置通过受信任 WebView 的无参数 `checkForUpdates` RPC 提供同一套原生交互。企业 Client 仅在原生桥接可用时提供此行，也支持 Client 激活后桥接才就绪的情况；浏览器部署隐藏此行。原生交互结束前按钮保持禁用，RPC 失败后可以重试。清单配置、发布认证和安装器路径仍由原生层拥有，设置入口因此无法选择其他发布者，也不会复制下载状态。

[本机安装包保护决策](2026-10-19-local-desktop-installer-protection.zh.md) 继续拥有产物构建和混淆规则，发布认证不取代它。[原生退出决策](2026-10-10-desktop-work-plugin-capabilities.zh.md) 继续拥有 Runtime 生命周期。[桌面端发布说明](../../../../apps/electrobun/README.zh.md#desktop-updates) 拥有密钥配置和清单发布操作。

[Admin 版本发布](2026-10-21-admin-desktop-release-publication.zh.md) 负责 API 上传、私有制品存储和串行发布；本文保留原生版本认证和安装器交接的决策依据。

[macOS 公证](../process/2026-10-21-macos-release-notarization.zh.md)在更新元数据签名前完成 Apple 票据与校验和处理。

## Alternatives considered

**Electrobun 自动增量更新器。** 完整且经过验证的 DMG/ZIP 产物复用本机安装包，并让用户明确执行替换。自动补丁需要独立的产物和安装协议，此发布路径不需要它。

**仅使用 TLS 和 SHA-256 校验文件。** 控制产物存储的攻击者可以同时替换安装包和校验文件。嵌入已可信客户端的公钥可独立于存储验证元数据。

**Runtime 运行时静默替换。** Runtime 和 Windows 安装包包含原生可执行文件及共享资源。交接前停止所拥有的任务可避免替换与任务重叠；macOS 替换仍由用户在 Finder 中明确执行。

## Consequences

静态 HTTPS 托管无需持有发布私钥即可分发已认证的完整安装包。先上传不可变产物，再发布清单。没有固定更新配置的构建会解释更新不可用。轮换密钥需要另一个可信安装包。旧客户端无法自动获得此更新器，签名清单也不替代 Apple 公证或 Authenticode。不提供自动重启、增量协议、数据降级或后台轮询。成功交接后保留临时文件供外部安装器访问，最终由操作系统清理临时文件。

针对性测试认证签名载荷，拒绝签名、平台、URL、大小和哈希错误；基于屏障的测试覆盖取消、迟到对话框和先清理再交接。本地预期输出固定原生提示，不虚构 Session 记录。签名器作为真实子进程，使用临时密钥和 fixture 产物运行。Windows Setup 交互安装、macOS DMG 替换、操作系统信任对话框和全新机器升级需要在对应平台验收。
