# Agent Note: Chat 历史延迟渲染

Status: implemented

[English](2026-10-25-chat-offscreen-rendering.md) | 中文

## 问题

一千轮对话可能包含数千个 Chat Seat、Markdown 树和工具视图。切换 Session 时重新挂载整个已加载 transcript，即使读者只需要尾部或保存的位置，也会阻塞主线程。Session scope 和插件注册已经能跨切换保留；渲染工作需要单独限制。

## 决策

Chat 将连续节点组织为稳定的 Turn 分段，挂载保存的阅读位置附近及实时尾部。部署配置控制每段 Turn 数、初始分段数、视口预加载范围，以及未测量 Turn 的预估高度。连续的延迟分段共用一个高度占位。交叉观察器对实测或预估的偏移量执行二分查找，只挂载接近视口的分段；占位 DOM 因此随已访问区域而不是历史总长增长。按动画帧合并的滚动监听器在巨大占位内展开视口附近的分段，即使其交叉状态没有改变。分段挂载后，其 Seat、订阅、DOM 和工具本地状态保留到视图卸载。运行中的工具结束时，节点的分段归属保持稳定。已挂载分段使用自然布局，不使用绘制包含，保留宽表格溢出。

声明的 Session 级 Chat store 在视图重新挂载之间记住实测分段高度和嵌套锚点标识。相同视口宽度下的测量值用于占位，其余分段使用估算。延迟内容隐藏后批量读取分段高度，由一个观察器更新尺寸。布局清理在行引用分离前保存当前阅读锚点，包括滚动采样仍待处理时的导航。挂载时保持读者的可见锚点；处于尾部的读者继续跟随实时底部。已加载 Turn 的导航先请求目标分段，再定位；未加载导航保留连续窗口分页器。[历史阅读决策](2026-10-26-chat-history-reading.zh.md)拥有自动分页与跟随归属规则。

空闲任务提取载荷搜索文本，并在索引完成后统一发布；不支持空闲回调的浏览器使用定时器任务。延迟分段在 `hidden="until-found"` 下保留节点载荷的可搜索文本叶节点。浏览器 `beforematch` 同步挂载匹配的延迟区域，同时保留其首个展开容器；这种显式查找可能挂载很大的区域。标准查找快捷键会挂载全部已加载的富文本 transcript，包括从输入框调用时。在可编辑字段之外，全选也会如此；编辑器内的选区仍限于本地。不支持可搜索隐藏内容的浏览器依赖键盘查找路径搜索延迟历史。原生菜单查找、节点载荷中不存在的自定义 renderer 文本，以及跨越未访问延迟分段的选区，仍存在取决于浏览器的限制。

Chat 在节点顺序变化时确定最后一个用户 key 并发布 `data-actions-reveal`；CSS 不搜索后续用户兄弟节点。导航索引更新受影响的预览，而不复制未变化的历史。[过程折叠](../feature/2026-08-14-web-turn-process-folding.zh.md)、[稳定排序](../bug-fix/2026-08-26-stable-turn-process-order.zh.md)和[视口高亮](2026-08-31-viewport-activated-syntax-highlighting.zh.md)决策继续分别拥有交互与缓存规则。

## 考虑过的替代方案

**离开视口时卸载已访问分段。** 这能限制 DOM 内存，但会丢弃工具本地状态，并破坏跨已访问消息的选区。保留已访问分段可以限制初始渲染工作，同时在本次访问中保留这些交互。

**隐藏保留每个 Session 的 React 树。** 非活动订阅和 DOM 会随已访问 Session 增长。延迟重新挂载保留现有 Session 隔离，只在视图 store 中缓存几何数据。

**为每行应用绘制包含。** 包含会裁剪宽表格溢出，由估算引起的底部变化还可能干扰键盘 End。显式分段挂载将几何变化与滚动归属协调起来。

## 影响

Session 切换挂载阅读位置附近的内容，而不是所有已加载消息。事件存储、节点投影、可搜索文本提取和提纲大小仍随已加载历史增长；这不是历史淘汰机制。单个巨大的 Turn 或富内容 renderer 仍可能主导其所在分段的耗时。显式查找和全选可能执行与历史等长的工作。可选性能测试默认使用 1,000 个 Turn，并接受 `DSH_PERF_HISTORY_TURNS` 以测试更大的历史，其值为 100 的整数倍。测试独立于已挂载行数检查已加载数量，并将可信点击到可见回答帧的耗时与 Playwright 命令开销分开报告。受保护 Client bundle 可以独立于原生窗口外壳进行测量；低于 100 毫秒的目标需要在实际部署和主机上实测。
