# Agent Note：使用全平台模型目录

Status: implemented

[English](2026-09-14-platform-wide-model-catalog.md) | 中文

## 问题

模型可用性原先由按组织保存的授权记录表示，并包含组织级启用状态、默认选择和优先级。这个额外的管理界面不符合“平台上架模型后所有组织都可以使用”的产品规则。

## 决策

平台模型目录是可用性的唯一来源。`enterprise_auth.model` 中启用的记录会出现在每个已认证组织的模型目录中，并可由网关受理。平台管理员通过创建、编辑、启用、停用或删除记录控制上架状态。API 和控制台不再提供组织模型授权、默认模型或优先级。迁移 `0009_platform_wide_models` 删除废弃的 `enterprise.model_grant` 表。

组织认证、Runtime 租约、策略修订号、预算、限流和模型地址校验仍然必须通过。平台停用模型后，该模型会从所有组织目录中消失，并拒绝新的调用。

## 备选方案

**保留组织授权并自动创建。** 不予采用，因为这会保留冗余状态和产品不需要的按组织管理流程。

**保留授权作为例外覆盖层。** 不予采用，因为可用性会依赖两个来源，并重新引入默认模型、优先级和组织级失败模式。

**移除模型启用状态，所有已保存记录都自动上架。** 不予采用，因为平台管理员仍需要一个全局开关来停止所有组织使用某个模型。

## 影响

模型目录更小且确定：平台上架是唯一的模型可用性决策。已有部署必须执行删除旧表的破坏性迁移；旧授权记录不会作为兼容数据继续解释。即使模型可用性改为全平台，组织访问控制仍保护租户数据和费用。

## 测试

API 集成套件验证：没有任何授权记录时，启用模型会出现在两个组织的目录中；停用后从目录中消失。网关计量测试在不插入组织授权数据的情况下调用启用模型。桌面端和客户端测试使用平台可用性术语，并继续拒绝未知模型 ID。
