# Agent Note：目录同步采用标准分页和抽样预览

Status: implemented

English | [中文](2026-10-02-enterprise-directory-sync-pagination.md)

## Problem

原来的目录脚本只返回一个没有上限的对象。管理员看不出企业字段如何转换成组织和账号，大型目录还会同时在 worker、预览数据库和浏览器中完整展开。

## Decision

目录脚本继续兼容原有数组返回格式，同时支持标准分页返回格式。分页实体包含 `items`、可选的 `nextCursor` 和可选的 `total`。标准实体为 `organizations`、`users` 和 `memberships`；每条记录使用稳定的 `externalId`，关系通过对应的外部 ID 关联。预览每种实体每页最多接收 1000 条，只保存数量、游标信息和少量抽样，并在该页范围内生成有上限的差异记录。管理员按源系统游标逐页预览、审批、重试和回滚。

管理端脚本弹窗提供企业接口、LDAP、表格/数据库三种模板，并展示企业字段转换示例、输入示例、输出字段和游标流程。原有数组脚本仍可执行。

## Alternatives considered

- **继续返回完整结果**：会保留大型目录的内存和浏览器上限问题。
- **在沙箱中臆造异步生成器 API**：当前 worker 只执行一次函数调用，没有持久化网络或调度能力。
- **使用数组下标作为标识**：分页变化后下标会变化，可能造成账号或组织重复。

## Consequences

- 企业源连接器需要拉取一页数据，把该页传给脚本，再用 `nextCursor` 继续。
- 预览有意采用抽样，不会把该页所有记录发送到浏览器。
- 页面通过现有审批流程创建或更新组织、用户和成员关系。未支持的源字段会保留在待审记录中，不会被静默应用。

## Verification

管理端和 API 类型检查、API 同步执行器测试以及 `git diff --check` 已通过。
