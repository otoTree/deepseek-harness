# Agent Note: Arivo 视图移除前的编辑器离开确认

Status: implemented

[English](2026-10-24-arivo-editor-departure.md) | 中文

## Problem

iframe 编辑器内部切换可以等待 SQLite 确认，但外层 Rail 或 Workbench 移除文档时不会调用该检查。`beforeunload` 不能保护 iframe 移除。回复丢失后，写入可能已经落盘，原稿和原命令身份仍在编辑器中等待确认。

## Decision

Arivo 启动插件拥有离开租约。主导航提供单一可选切换处理器，Workbench 标签与文件操作调用它。会话控制器独立提供单一可选选择处理器，覆盖显式用户导航。没有所有者的消费者保持同步行为。这些钩子不增加持久化、Provider 调用或模型可见状态。

父窗口使用新请求 ID 和精确目标来源，请所有已挂载 Studio iframe 准备离开。子页面只接受 Host 注入的父来源及父窗口，冻结编辑器与已打开弹窗，再执行既有本地保存检查。已编辑但未提交的表单拒绝离开。只有注册 iframe 对当前请求的精确确认才能授权离开；缺失、格式错误、迟到或拒绝的回复都会保留原页面。超时不代表允许。

同一输入事件中的同步回调共享一次确认，使会话选择与返回对话一起提交；保存等待期间的后续意图被拒绝。输入冻结持续到同步 React 提交结束，再释放。编辑器集合改变或启动插件卸载会取消待执行导航。语言与主题触发的 iframe 重载使用相同机制；Arivo Workbench 入口等待会话可寻址后才启用。

Arivo 原生菜单退出和用户关闭窗口会先同步否决原生销毁，再向同一协调器申请持续冻结。一次性有界 loopback 回执只接受当前 OS 来源、请求 ID 与决定字段；沙箱页面不获得通用原生 RPC。缺少启动代码、脏弹窗、保存失败、超时或运行时代次失效均拒绝退出；已确认后同时将 OS 文档设为 inert，阻止稍晚挂载的 iframe 接收输入，冻结持续到运行时等待停止结束；释放恢复文档原先的 inert 状态。释放会取消迟到准备，并在退出失败后恢复输入。信号停止与强制终止保留现有未保护语义。

## Alternatives considered

**依赖 `beforeunload`。** iframe 移除可能绕过它，父窗口无法区分已保存草稿和未确认写入。

**在浏览器存储业务草稿。** 这会增加第二个持久化所有者，并使 Host 的账号 epoch 和 SQLite 修订规则复杂化；离开检查复用现有 Worker 命令与回执。

**对所有产品无条件启用检查。** 企业消费者保留现有同步行为，只有显式启动所有者会启用异步协调。

## Consequences

启动插件依赖随包 Harness 的新可选选择钩子，共享依赖版本不变。独立创作插件仍仅消费经过验证的发布产物。强制终止、Host 权威账号/列表变化与注册卸载不因这些 UI 钩子获得编辑安全保证，仍需各自的实现和验收。本决策补充[原生浏览器保留机制](2026-10-16-shared-browser-page.zh.md)，不替代其资源生命周期。
