# Agent Note：提供方无关多模态模型输入

Status: implemented

[English](2026-09-17-provider-neutral-multimodal-inputs.md) | 中文

## Problem

企业能力元数据让协议和模态支持可以配置，但请求路径仍只处理持久图片和内联 Chat Completions。视频、音频和文档需要持久的提供方无关表示、已校验字节、有界提供方文件生命周期、Responses 流式处理与用量对账，同时不能把提供方协议分支移入 Agent Loop，也不能暴露存储 URL。

## Decision

LLM 词汇加入由持久附件引用支持的 `video`、`audio` 和 `document` 块。通用旧 `file` 块继续可读，而且只有在字节检查记录可用 MIME 类型、精确模型同时声明对应模态与原生文件策略时才会被提升；否则原有的确定性保存路径文本继续对模型可见。此改动不增加 Session 事件代次，也不改变事件信封，因此 `SESSION_FORMAT_VERSION` 保持不变。Session 数据保存内容寻址附件 id、种类、已校验 MIME 类型、清洗后的名称和字节数，但绝不保存字节、Base64、提供方标识符、凭据或对象存储位置。

`@deepseek-ai/dsh-llm-files` 是可复用 Files API capability。适配器注册提供方实现，并按提供方、非秘密账号命名空间、模型和内容摘要解析文件。进程内缓存共享并发上传、在过期前刷新、支持等待方独立取消、有界重试、一次配额恢复尝试、显式失效与提供方拥有的删除。仅当进程内回执属于调用方组织、账号和模型时，企业 API 才接受提供方文件标识符。缺少回执或模型端点拒绝会触发一次协调的失效、上传和请求重放；第二次拒绝会直接失败，不再重放。首个仍在等待的调用方会为用量统计认领物理上传，提供方文件标识符绝不进入 Session 状态或诊断信息。

现有企业网关适配器拥有 OpenAI Chat Completions 与 Responses 序列化。它按所选模型策略投影已校验附件，对不支持的协议字段组合与限制关闭式失败，把 Responses reasoning-summary 增量映射为提供方无关的 reasoning 块，拒绝未知流事件，使用提供方无关的失败 code 分类 HTTP 限流与超时，并保留函数调用和工具结果历史。API 中继校验规范化模态声明、拒绝永久远程媒体 URL、通过服务端凭据上传、透明转发所选协议端点，并在流不完整或用量无效时记录已完成用量或待对账状态。Ark 兼容逻辑仍只位于此适配器与中继；Agent Loop 保持不变。Anthropic Messages 与签名 URL 投影尚未实现，不能被声明为可用组合。

## Alternatives considered

**在 Agent Loop 中加入 Ark 与 Responses 分支。** 不采用，因为模型协议和文件传输是适配器职责。loop 分支会让一个企业提供方改变所有组合，并在已注册适配器之外重复请求投影。

**持久化提供方文件标识符或永久对象存储 URL。** 不采用，因为两者都是受授权范围约束的运行时事实，其生命周期不同于 Session 历史。持久日志只保留附件身份和已校验元数据；每个请求都从附件权威来源派生临时提供方引用。

**把客户端 MIME 声明视为权威。** 不采用，因为它跨越网络和持久化边界。附件后端从文件字节识别 PNG、JPEG、WebP、GIF、文档、音频和视频签名，只用清洗后的叶文件名区分容器格式，并拒绝与内容冲突的受支持声明类型。

**在 Files API、Base64 和 URL 间静默回退。** 不采用，因为传输方式变化会改变暴露面和请求限制。所选模型策略具有权威性：有界内联字节保持内联，提供方文件路由执行上传，不可用或不兼容策略在上游模型分发前失败。

## Consequences

现有文本、图片和通用文件 Session 继续解码，旧模型通过能力默认值保持此前的文本或图片行为。有能力的企业模型可以通过任一 OpenAI 协议消费图片、视频、音频和文档，而不暴露永久存储地址。Admin 拥有协议、模态、策略、大小、TTL、模型调用与上传超时、重试和清理配置；桌面模型目录与选择器消费相同事实。API 拥有模型调用截止时间，桌面会增加传输宽限期，使上游超时能够到达调用方，而不会与本地取消竞争。用量记录区分协议、模态、文件上传次数与字节、上传失败、已结算调用和待对账状态。提供方文件缓存状态按设计会在进程重启时丢失，并可能触发安全重传。

## Testing

单元覆盖检查 PNG、JPEG、WebP 和 GIF 签名、声明类型不匹配拒绝、旧文件提升、四类媒体序列化、Responses 文本、reasoning-summary 与函数调用流、格式错误的关键事件、上传 singleflight、取消、过期刷新、重试、配额恢复、失效与清理。企业集成覆盖贯穿光栅图片及其他附件读取、提供方上传、并发复用、Chat 与 Responses 请求体、严格流完成、模型调用超时传播、HTTP 失败分类、用量结算与待对账、永久 URL 拒绝、声明模态不匹配、字节限制、过期运行时策略和提供方文件过期清理。无密钥限流场景证明提供方无关的 `RATE_LIMIT` 失败会通过已发布 headless profile 进入持久 Session 状态。真实提供方测试保持可选，并在没有凭据时跳过。
