# Agent Note: 开发索引是必读的代码导航图

Status: implemented

[English](2026-10-03-development-index.md) | 中文

## 问题

仓库已有架构、包、子系统和生成图文档，但 agent 仍需要一个查找入口，把改动类型连接到源代码所有者、入口、测试和约束文档。根 `AGENTS.md` 还携带一份可能与工作区漂移的包摘要。

## 决策

仓库在 [`docs/development-index.md`](../../../../docs/development-index.zh.md) 维护一份人工维护的双语开发索引。索引包含仓库根目录、运行时路径、包组和文件约定四层。它只记录导航和所有权事实；包行为仍由包 README、子系统约定、架构文档、生成目录和源代码负责。

根 `AGENTS.md` 要求 agent 在修改代码前阅读对应索引层，再阅读目标源代码、测试、包 README 和适用的子树指令。代码或结构改动导致已列出的目录、包、入口、所有者、生成产物或开发路径发生变化时，必须在同一改动中更新索引。文档检查会校验配对索引和链接；索引不加入生成图流水线，因为其中的改动到文件指引需要人工维护判断。

## 曾考虑的替代方案

**把包摘要留在根指令中。** 摘要必须出现在每个 agent 上下文中，但无法容纳运行时路径、测试所有权或文件级指引。把详细地图移到链接文档可以保持常驻指令简洁，并让地图只有一个所有者。

**只使用生成的模块图和文档图。** 这些图回答依赖和文档关系，但不能指出某类行为改动首先应读哪些源文件，也不能指出相关测试和快照所有者。索引链接到生成图，不复制其中的边。

**从目录名生成索引。** 目录发现无法推断所有权、启动路径、生成源规则或正确测试。索引保留人工维护这些事实，同时用包清单和链接检查提供新鲜度证据。

## 后果

agent 在实现前有一个统一的导航步骤，根指令不再重复一份会陈旧的包组摘要。仓库维护者必须在结构或开发所有权变化时更新索引。client 包清单列出当前每个 UI 包，并将没有包组 README 的 `packages/model/` 指向清单和源代码；每行的精确包约定仍由所列文件负责。
