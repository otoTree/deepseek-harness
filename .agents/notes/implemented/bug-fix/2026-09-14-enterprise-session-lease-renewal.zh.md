# Agent Note：空闲时续租企业 Session 写权限

Status: implemented

[English](2026-09-14-enterprise-session-lease-renewal.md) | 中文

## 问题

企业 Session 的写权限会在服务端空闲过期。原生 provider 只在追加事件和 flush 时续租，因此 Session 安静一段时间后，用户下一次写入会收到 `write ownership was lost`，即使桌面 Runtime 仍然活跃。

## 决策

每个远程写句柄根据服务端返回的 `leaseUntil`，在剩余租期的一半时安排下一次续租。续租通过句柄自己的串行队列执行；定时续租失败会冻结句柄，下一次写入报告稳定的所有权错误。关闭句柄会取消定时器，并继续释放服务端租约。

## 备选方案

**使用固定续租间隔。** 不予采用，因为租期由 API 决定，不同部署可能配置不同的时长。

**所有权丢失后自动重新打开句柄。** 不予采用，因为新写入者可能与其他所有者重叠并破坏单写者保证；调用方必须显式关闭并重新打开。

## 影响

只要认证 Runtime 仍然活跃，空闲打开的 Session 就能保留写租约。续租失败不会复活过期句柄，关闭句柄仍负责释放所有权。

## 测试

完整 Electrobun 测试套件在续租定时器启用后通过；网关、桌面生命周期、配置文件和持久化集成路径仍受覆盖。
