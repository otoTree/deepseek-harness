# Agent Note：私有插件同版本重传与有界中断

状态：已实现

[English](2026-10-04-enterprise-plugin-reupload-interruption.md) | 中文

## 问题

当 plugin ID 和版本不变时，包唯一性约束会拒绝私有开发包的重复上传。Client target 的原生窗口关闭操作如果不返回，也可能阻塞协调流程。

## 决定

包接口把已发布的相同私有包视为幂等请求。如果这个私有 release 曾被强制清除撤销，重新上传相同包会重新发布它并清除撤销时间。私有包内容变化时，替换已有私有 release，递增安装授权修订号、撤销激活，并让设备重新加载新归档。公开 release 仍不可覆盖。Client 窗口清理使用现有清理截止时间；浏览器 SDK relay 把中断信号继续传入 Connection RPC。插件市场在安装存在新版本时仍保留恢复操作；过期的 target preparing 记录不会让仍处于活跃状态的安装永久不可用。强制清除使用应用内确认；其组织路由纳入 Runtime token 鉴权，同时仍根据已认证账号检查个人所有权。服务端撤销结果与本地 Client 的尽力协调结果分开报告。启用、升级、卸载和强制清除在控制面变更完成后立即返回，本地协调独立在后台进行。

## 结果

私有开发包可以在不修改版本号的情况下重新构建和上传。强制清除撤销的私有 release 在重新上传相同包后会再次显示，内容变化的包则替换原 release。替换会重启活跃安装，但保留安装数据空间。窗口关闭卡住时，截止时间后会记录清理失败，但 lease 撤销和 SDK 失效仍会继续，后续协调可以重试清理。目录显示新版本时，用户仍可停用、卸载或强制清除安装。个人强制清除现在与其他生命周期操作使用相同的 Runtime token 路径。本地协调卡住或不可用时，只要服务端变更成功，操作仍报告成功；真正的桥接失败会在市场提示中显示返回的错误信息。

## 测试

企业身份 fixture 覆盖内容变化和内容相同的私有同版本上传、强制清除后重新发布相同包、组织能力响应，以及使用 Runtime token 的个人强制清除。企业 runtime 测试覆盖卡住的 Client 窗口关闭；Client runtime 测试继续覆盖 target 协调和清理截止时间。企业 Host bridge 套件覆盖初始 catalog 读取卡住时仍能完成强制清除。企业 Web 客户端套件覆盖 active/preparing target 混合状态、应用内强制清除确认、服务端与本地协调结果分离、桥接错误信息和升级卡片的恢复操作。

仪表盘还会返回服务端计算的组织插件能力。Web 客户端使用这些能力隐藏非私有上传选项，并对当前策略不授权的账号禁用组织安装变更操作。

## 备选方案

保留版本唯一性错误会迫使每次私有开发构建都修改版本，也无法解决安装卡住的问题。没有采用替换公开 release，因为目录消费者依赖其摘要和发布状态保持稳定。
