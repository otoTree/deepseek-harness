# Agent Note: 不让过期 Runtime 占用注册额度

Status: implemented

[English](2026-09-14-expired-runtime-quota-recovery.md) | 中文

## 问题

桌面客户端停止续租心跳后，Runtime 租约会过期，但额度准入逻辑仍会统计所有未撤销记录。因此旧设备租约过期后，客户端仍可能失去访问，过期记录会继续占满组织的 Runtime 额度。

## 决策

桌面授权交换和带认证的 Runtime 注册只统计 `revokedAt` 为空且 `leaseUntil` 晚于准入时间的记录。过期记录继续保留，以供管理和审计；活跃客户端仍可通过心跳路由续租。新租约使用与额度检查相同的时间戳计算。

## 备选方案

**要求管理员手动撤销每条过期记录。** 不予采用，因为租约过期已经是服务端权威的存活信号；手动清理会把正常断线变成额度故障。

**在准入时删除过期记录。** 不予采用，因为 Runtime 历史对管理和审计仍有价值，而且释放额度不需要删除记录。

**只在桌面授权路径忽略租约过期。** 不予采用，因为带认证的 Runtime 注册路径仍会发生同样的故障，两个注册入口也会出现不一致的额度行为。

## 影响

旧租约过期后，组织可以注册新的桌面 Runtime，而不需要破坏性清理。过期记录仍可见，也可以显式撤销。Runtime 必须持续发送心跳才能继续占用有效额度槽位。

## 测试

`apps/api/tests/identity.test.ts` 用两个过期且未撤销的记录占满组织额度，并验证桌面授权和 Cookie 认证的 Runtime 注册都仍能注册新的 Runtime。API 类型检查和聚焦的身份测试覆盖了修改后的准入路径。
