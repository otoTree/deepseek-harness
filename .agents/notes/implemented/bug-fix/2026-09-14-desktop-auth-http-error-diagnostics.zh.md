# Agent Note: 显示桌面授权交换失败详情

Status: implemented

[English](2026-09-14-desktop-auth-http-error-diagnostics.md) | 中文

## 问题

桌面客户端将所有非成功的 `/desktop/token` 响应都压缩为 `Desktop authorization exchange refused`。这个消息无法区分授权码被拒绝和组织运行时额度用尽，运维人员必须查看服务端日志或数据库后才能选择处理方式。

## 决策

桌面客户端使用与成功凭据相同的 8 KiB 有界读取器读取失败响应。抛出的错误包含 HTTP 状态码和非敏感的 `message` 字段（或有界的纯文本）；当中间层没有响应体、响应体过大或无法读取时，保留仅含状态码的通用错误。凭据响应仍受大小限制，返回的设备元数据不会包含令牌。

## 备选方案

**继续使用一个笼统的错误字符串。** 不予采用，因为它隐藏了授权失败（403）与运行时额度耗尽（409）之间可直接行动的区别。

**暴露完整响应体。** 不予采用，因为中间层可能返回无界响应，或包含不适合显示在桌面错误消息中的数据；实现有界读取，并优先提取服务端消息。

**自动修改运行时记录来解决失败。** 不予采用，因为额度和授权状态由服务端管理，未经运维人员确认删除或撤销运行时具有破坏性。

## 影响

终端日志现在会显示 HTTP 类别和 API 消息，例如 `Desktop authorization exchange refused (409): Runtime limit reached`。客户端仍不会在抛出错误或结果元数据中携带平台令牌。运维人员可以根据首次失败报告选择重新认证、检查授权码流程或处理额度。

## 测试

`apps/electrobun/tests/desktop-auth.test.ts` 验证 403 和 409 JSON 消息会出现在有界错误中。桌面授权测试和 TypeScript 检查均通过。
