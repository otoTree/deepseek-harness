# Agent Note: 企业客户端请求以服务端 Runtime 租约为准

Status: implemented

[English](2026-09-14-enterprise-client-renewed-runtime-lease.md) | 中文

## 问题

企业仪表盘、模型设置和插件目录共用一个 Host RPC 桥。Keychain 中登录时记录的 `leaseUntil` 经过后，桥接会拒绝该凭据，即使原生心跳已经在服务端续租 Runtime。结果是三个设置页面会在一个初始租约周期后同时变为不可用。

## 决策

Host 桥会在每次企业请求前验证保存的 API 来源、组织 ID、Runtime ID 和 Keychain 账户绑定，但不使用登录响应的 `leaseUntil` 快照判断当前存活状态。企业 API 仍是权威来源：每个认证请求都会解析 Runtime 令牌，并拒绝服务端已过期、已撤销或不匹配的记录。原生心跳继续续租服务端记录，并在续租失败后停止托管 Runtime。此包的 Host 和 Client 编译面会分别构建，Host 编译面也会加入桌面插件构建，因此桥接使用的是已发布的源代码。

## 备选方案

**每次心跳后重写 Keychain 凭据。** 不予采用，因为租约续期已经在服务端提交；反复写入密钥存储会引入第二次状态更新，它可能在续租成功后失败，从而产生同样的不一致。

**继续在本地拒绝初始租约快照。** 不予采用，因为该时间戳无法表示后续续租，并且必然使长时间健康运行的桌面会话失效。

**删除所有 Host 凭据检查。** 不予采用，因为桥接仍必须阻止生成的 profile 使用属于其他部署、组织或 Runtime 的凭据。

## 影响

只要服务端接受持续心跳的 Runtime，企业账户、模型和插件设置就会保持可用。撤销、租约过期、组织不匹配和部署不匹配仍会由权威 API 或 Host 绑定检查拒绝。服务端不可达时，对应页面仍会显示不可用并允许重试。标准包构建会在打包桌面插件前先生成更新后的 Host 桥。

## 测试

Host 桥测试保存一个初始 `leaseUntil` 已经过期的值，并验证带认证的仪表盘、模型、Runtime、用量和插件请求仍然成功。另一项测试验证不匹配的部署来源仍会在发送请求前被拒绝。
