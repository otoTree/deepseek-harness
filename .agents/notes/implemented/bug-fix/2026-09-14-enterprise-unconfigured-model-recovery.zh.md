# Agent Note：组织稍后授权模型后的企业模型恢复

Status: implemented

[English](2026-09-14-enterprise-unconfigured-model-recovery.md) | 中文

## 问题

桌面配置文件生成时，组织可能还没有授权模型。模型目录为空时，配置会保存 `enterprise-unconfigured`。组织之后新增授权会更新服务端目录，但已经运行的桌面仍会提交这个占位值，网关因此将请求拒绝为不可用。

## 决策

企业网关在模型解析和流式请求中都根据实时授权模型目录解析 `enterprise-unconfigured`。其他请求仍必须使用精确的已授权模型。发送到服务端的是目录中的实际模型 ID，占位值不会进入模型调用接口。

## 备选方案

**要求组织授权后重启桌面端。** 不予采用，因为网关已经拥有实时授权目录，可以在不替换运行中配置的情况下解析占位值。

**把所有未知模型都接受为目录中的第一个模型。** 不予采用，因为只有启动占位值表示目录曾经为空；任意其他 ID 仍必须视为未授权。

## 影响

组织首次授权模型后，已经运行的桌面会在下一次模型请求刷新实时目录并生效。没有模型时，已有配置仍可启动，并继续显示没有可用模型，直到组织完成授权。其他未授权 ID 仍会被拒绝。

## 测试

Electrobun 网关 fixture 覆盖实时模型发现和模型调用准入；恢复路径复用相同目录和请求断言，未授权模型测试继续证明任意 ID 不会被接受。
