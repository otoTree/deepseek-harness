# Agent Note: 企业设置按任务划分页面

Status: implemented

[English](2026-10-09-enterprise-settings-task-ownership.md) | 中文

## Problem

账户设置重复展示模型目录和个人用量，插件设置则重复展示缺少安装操作的市场目录。用户必须自行判断哪个页面负责操作。有限的用量记录页也无法得出完整月度总量。

## Decision

企业账户负责组织身份、订阅、角色和设备。模型负责默认模型选择及能力目录。通讯录默认展示成员，再按需打开所选成员的资料和独立的受权限控制的调用记录标签页；邀请有单独视图。账单将个人周期汇总、调用记录和共享钱包流水分开。用量提供近 3、7、30 天和自定义日期。Host 汇总请求周期内的全部 API 分页，其他设置读取不请求用量。设置是与云盘、插件市场并列的应用主页面。这些页面显示固定的一级应用导航和各自导航；会话侧栏与 Session 控件保持隐藏，侧栏偏好不被改写。邀请和兑换表单在其上打开共享模态框。`main.surface` 按 key 为各页面分配独立所有者；侧栏引导链接与设置页面共享分类选择 store。企业插件设置链接至插件市场，市场仍是唯一的目录与安装界面。

页面使用低对比度描边分区和对齐控件。模型选择器显示名称，完整 ID 保留在目录详情中。金额保留完整精度。根据内容栏宽度纵向排列筛选器和财务摘要。共享模态框限制键盘焦点范围，关闭后将焦点还给打开按钮，并在设置上方显示时独立响应 Escape。

[团队钱包](../feature/2026-09-18-team-cny-wallet.zh.md)和[插件市场](../feature/2026-09-19-enterprise-plugin-marketplace.zh.md)决策继续负责授权、计费和包生命周期。本决策仅涉及设置导航和呈现。

## Alternatives considered

模态设置外壳会让操作弹窗嵌套在另一弹窗中，并妨碍应用导航。在账户页保留摘要副本会形成相互竞争的入口，并要求用户自行核对不同统计窗口。完全删除插件设置入口则会降低在设置中寻找插件管理功能的用户的发现效率。

## Consequences

用户在一个明确入口完成各项任务，按需打开详情或操作。模型页在默认选择器旁展示能力限制，目录为空时禁用选择。记录进入视图后才加载，并独立分页；切换周期时丢弃过期响应。周期汇总需要读取全部 API 分页，因此大量历史记录会增加请求耗时。组件测试和基于会话的浏览器快照覆盖导航、筛选、分页、单层操作弹窗及窄屏布局；原生桌面验收仍独立进行。
