# Agent Note: 移除企业模型来源允许列表

Status: implemented

[English](2026-09-14-remove-model-origin-allowlist.md) | 中文

## 问题

企业部署只有一个平台超级管理员，但保存模型前还要求单独配置来源允许列表。缺少环境变量会让原本有效的公网模型地址以含义不清的 400 失败，并给不匹配当前所有权模型的部署增加配置工作。

## 决策

模型目录接受任意公网 HTTPS 地址。网关仍会拒绝 URL 中嵌入的凭据、查询参数、片段和字面 IP 地址。连接时的 DNS 查询会在发送已保存的模型凭据前拒绝指向受禁止私有及特殊用途 IPv4 网段的结果。每个模型的 API Key 仍加密保存，模型写入仍仅限平台超级管理员。

移除来源允许列表配置和生成的环境变量。如果部署以后需要按目标地址限制请求，必须在所属部署层加入显式策略，而不是为所有安装重新引入必填设置。

## 备选方案

**保留必填允许列表并补充文档。** 不予采用，因为它把单一管理员的本地流程变成两步配置，并且在模型请求之前失败，无法提供有用诊断。

**不保留传输和 DNS 检查，允许所有 URL。** 不予采用，因为仅要求 HTTPS 仍无法阻止 URL 组件中的凭据，或 DNS 解析后访问内网地址。

**让允许列表可选，空值表示不限制。** 不予采用，因为这会保留两种运行模式和已经不需要的配置面，却没有给当前单一管理员部署带来收益。

## 影响

平台超级管理员无需编辑环境文件即可保存任何兼容的公网 HTTPS 模型服务。服务端继续保护风险最高的出站目标，且不会在租户响应中暴露已保存的密钥。需要固定供应商集合的部署不再从本包获得该控制，重新引入前必须先提供明确的网络或部署策略。

## 测试

网关测试接受多个公网 HTTPS 来源，并继续拒绝明文、携带凭据、带查询参数和字面 IP 的 URL。移除配置字段后，API 与管理端类型检查、模型容量回归测试和 API 构建均通过。
