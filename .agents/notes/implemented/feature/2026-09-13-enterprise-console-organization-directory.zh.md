# Agent Note：企业管理端统一组织目录与账号控制面

Status: implemented

[English](2026-09-13-enterprise-console-organization-directory.md) | 中文

## 问题

管理端把租户单元、平台组织、账号和模型设置混在一个页面中，平台管理员无法查看全局组织树或账号跨组织资源，模型授权也缺少默认和优先级状态。

## 决策

管理端提供全局组织、账号、审计和模型配置页面，同时保留当前组织页面。组织树初次只读根节点，展开时加载直接子节点；选择节点只设置当前上下文，不隐式包含后代。账号详情按标签页加载组织、角色、设备、会话、用量和历史。模型授权在统一组织模型表中保存启用、优先级和默认状态，并保证每个组织最多一个启用默认模型。

平台管理员读取受 RLS 保护的资源时设置事务级平台标记，写入仍要求明确组织并保留审计。open 与 private 部署继续共用组织、成员、角色、资源和模型授权表。

## 备选方案

- 继续把平台数据放在租户概览中：会隐藏全局范围，并让无关请求相互耦合。
- 每次请求返回完整组织树：大型企业需要有界的根节点和子节点查询。
- 新建平台专用账号或模型表：会造成 private 部署分叉并破坏统一授权。

## 影响

管理员拥有明确的全局上下文，可在组织和账号视图之间切换。账号资源需要按标签页额外请求；模型只有在启用且明确授权后才能设为默认。原有租户接口保持兼容，平台接口逐步增加分页和筛选。

## 验证

企业 API 与管理端类型检查通过，两个包均构建成功。本地 enterprise API 已验证组织树、账号目录、账号资源标签页、模型目录和模型分配接口。真实本地浏览器流程录制为 `.playwright-mcp/super-admin-refactor.gif`。
