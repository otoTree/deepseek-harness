# Agent Note: 企业云盘使用按 ID 管理的对象存储与导航

Status: implemented

[English](2026-09-23-enterprise-cloud-drive.md) | 中文

## 问题

企业客户端已有插件市场主内容页面，但没有云盘导航协议。按路径实现文件界面会让授权和分页依据不明确。同名上传还必须避免覆盖已有文件，并在并发上传时保持对象、版本和目录节点的一致性。

## 决定

云盘由 `MainNavigation` 选择为 `main.surface`，企业客户端在侧边栏提供入口。打开云盘时保留当前会话，只有现有会话列表的打开路径可以切回会话。云盘请求使用不透明的空间 ID 和节点 ID，服务端每次检查租户权限，文件版本元数据使用不可变表，分页游标基于稳定的 `(name, id)` 排序。

文件内容通过带签名的 MinIO/S3 URL 存储，企业数据库保存不可变版本、描述、上传会话、编辑会话、审计事实和空间配额。Host Agent 工具和 Electrobun bridge 只接受不透明 ID，WebView 不接收持久凭据。目录、搜索和回收站使用绑定查询条件的游标，文本编辑生成新版本。

新文件上传会预留服务端生成的节点 ID，并在目标目录选择第一个可用名称。同名文件保留扩展名并追加数字后缀，例如 `(1)`；已有节点上传新版本时保留原名称。按目录使用事务 advisory lock 串行化命名，未提交且仍有效的上传会话也视为占用名称。

## 备选方案

**遇到同名文件直接返回冲突。** 否决：普通文件管理器上传不应要求用户先手工改名，产品也不能覆盖已有节点。

**上传后由客户端改名。** 否决：客户端无法在并发上传下安全选择名称，而且对象会在最终元数据确定前被创建。

**提交时才生成节点 ID。** 否决：签名对象键在提交前已经创建，上传会话预留 ID 才能保持对象、版本和节点身份一致。

## 结果

单一 `main.surface` slot 仍然有效，因为企业 dispatcher 根据 surface 判别值渲染插件市场或云盘。会话打开仍是返回会话的唯一交互，文件权限在每个 API 请求中根据当前租户和组织角色重新计算。
