# Agent Note: 触发器页面视觉层级

Status: implemented

[English](2026-10-14-trigger-page-visual-hierarchy.md) | 中文

## 问题

触发器页面把规则、实时队列和运行历史做成了三块同等宽大的面板。三者都为空时，重复的大面积底色压过了创建规则的入口，也让页面显得稀疏。

规则编辑器采用连续字段列表，原生控件高度不一致。事件来源设置、会话目标和指令缺少明确分组，较长的文件触发器表单还可能把保存操作挤出视口。

## 决策

触发器页面优先展示规则管理，并用紧凑空状态直接打开规则编辑器。实时队列和运行历史合并在带数量的标签面板中。规则启用状态与 Runtime 监听状态继续分开显示，现有规则操作和批次恢复操作仍保留在各自视图中。

编辑器使用共享 Modal 的 headless 模式，以固定标题和操作栏包围可滚动表单。三个编号字段组分别呈现触发条件、执行目标和 Agent 指令。语义主题令牌、等高输入框与选择框以及响应式双列网格保持字段对齐。提示词变量可在指令字段下展开，既保留入口，也避免抢占表单的视觉权重。

## 考虑过的替代方案

- **保留三块独立面板。** 否决，因为没有内容的队列和历史区域不应与规则管理占据同等视觉权重。
- **隐藏空队列和空历史。** 否决，因为首次事件到来前这两处仍是有用入口；标签保留其位置，同时避免预留大块空白。
- **保留不分组的连续字段列表。** 否决，因为随事件来源变化的设置会掩盖事件配置、会话投递与指令之间的区分。
- **让整个模态框滚动。** 否决，因为在较长的文件触发器表单和较矮的视口中，关闭与保存操作必须保持可达。

## 后果

用户可从空状态直接创建规则，队列和历史集中在一个次级区域。标签面板保留两个运行视图的可发现性，也避免重复使用大块面板底色。

编辑器内容独立于操作栏滚动。原生表单控件保留其输入行为，字段网格在窄视口中变为单列。组件测试覆盖事件来源与目标切换、匹配测试、创建、编辑和取消。
