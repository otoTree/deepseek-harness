# Agent Note：共享部门管理遵循部署策略

Status: implemented

[English](2026-10-22-deployment-aware-department-management.md) | 中文

## 问题

团队 Owner 可以管理邀请，却在桌面通讯录中找不到部门操作。账号入口也向私有化公司部署提供创建团队选项，而 API 会拒绝该操作。订阅名称无法区分这些部署策略。

## 决策

原生账号入口读取 API 公开的部署和注册策略。开放部署提供独立团队创建入口；私有化部署提供预建公司组织和邀请加入入口。关闭注册时隐藏账号注册入口。注册与接受邀请仍是独立操作；提交邀请后立即创建成员关系，无需管理员再次审批。

两种部署模式共用组织内的组织单元和成员归属。Owner 和管理员通过现有 API 及通讯录的“部门”标签页管理部门层级、选择活跃成员的归属部门。成员可以同时属于多个部门。根单元不可修改；删除部门需要确认，且仍有下级单元、成员归属或部门角色时会被拒绝。调整上级会拒绝循环及当前组织之外的引用。Runtime 凭据仅能在签发它的组织内调用这些 API。

[团队隔离决策](../bug-fix/2026-10-22-open-registration-team-isolation.zh.md) 负责成员关系继承规则。[身份提案](../../proposed/architecture/2026-09-05-enterprise-identity-and-organization.zh.md) 仍负责尚未实现的部门级委派及其他能力。[控制台通讯录](2026-09-13-enterprise-console-organization-directory.zh.md) 继续负责平台管理。

## 考虑过的替代方案

- 为 SaaS 和私有化公司分别建成员表，会使组织切换、计费和迁移行为分化。部署策略控制入口和继承，同一套记录负责成员关系与部门。
- 从企业订阅推断公司模式，会将部署策略绑定商业套餐，并错误标注独立团队。
- 删除部门时自动重新分配成员，会隐式改变部门共享资源的访问权。管理员须明确选择每位成员的新归属。

## 影响

部门管理不会创建计费组织或额外钱包。调整成员归属会影响按部门共享的云盘访问权。部门级角色仍可保存，但不授予部门管理委派权限。已有的显式成员关系、订阅套餐、余额和用量记录保留原归属。

[HTTP 回归](../../../../apps/api/tests/team-isolation.test.ts) 覆盖两种数据库凭据配置和两种部署模式。[原生账号浏览器测试](../../../../apps/web/tests/enterprise-account.e2e.ts) 使用内置账号页面检查策略驱动的入口，非 Session 预期输出保留在所属目录。[录制的通讯录场景](../../../../snapshots/web/enterprise-settings/snapshot.yml) 通过实际 Web 组合和 Host 桥接验证部门创建及成员归属。
