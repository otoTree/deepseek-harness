# Agent Note: 团队共享人民币钱包

Status: implemented

[English](2026-09-18-team-cny-wallet.md) | 中文

## 问题

人民币用量分析可以解释模型成本，但不持有可消费资金。兼容 subscription 预算使用另一种币种和语义，而把预算分别分配给成员或多个团队会使兑换与所有权变得含糊。产品需要每个组织一份可审计余额、一次性平台入账、fail-closed 准入和成员级归因，同时不能暴露其他成员的 Session 正文。

## 决策

每个组织拥有一个 `organization_wallet`，其整数微人民币余额从零开始。所有 active 成员共享该余额。只有余额为正时才能发起模型请求，否则 API 会在调用上游前返回 `402 INSUFFICIENT_TEAM_BALANCE`。网关不会预留最坏情况金额。因此，并发放行的请求结算后可以产生小额负余额，后续请求会继续被阻止，直到入账使余额重新为正。

`wallet_ledger` 是不可变的资金历史。正数 `redemption_credit` 引用一个兑换码，非正数 `model_usage_debit` 引用一条用量记录。对这些引用的唯一约束保证兑换、自动结算、重试和人工核对幂等。人民币用量结算会锁定用量与钱包记录，按 `totalCostMicrosCny` 精确写入扣款，记录结果余额，并在同一事务中把用量标记为 settled。待对账、失败、未定价和仅上传文件的记录不会扣款。旧 subscription 微美元字段继续保存用于兼容，但不参与人民币准入或钱包界面。

平台管理员使用十进制定点人民币金额创建 1–1000 个兑换码的批次。数据库保存 HMAC 和不可逆提示，绝不保存明文。明文兑换码只在创建响应中出现一次，以便立即导出。任意 active 成员都可以把一枚未兑换、未过期且未撤销的兑换码精确兑换一次到明确选择的组织；事务会标记兑换码、为钱包入账、写入账本并返回新余额。兑换后的码不能转移。

企业客户端向每个成员显示当前团队余额、兑换输入、个人当月用量和个人账本活动。Owner 和管理员可以查看团队通讯录、服务端聚合的自然日范围用量、游标分页成员记录和待处理邀请。管理员可以邀请 member；只有 Owner 可以邀请管理员。普通成员不能访问团队总量、通讯录或邀请操作。API 在配置的报表时区计算默认自然月，绝不根据有上限的客户端分页推导组织总量。

## 备选方案

**复用 `subscription.budgetMicros`。** 不采用，因为这些列表示兼容的微美元计费与预留。把它们改解释为人民币会破坏现有含义，并保留不需要的最坏情况预留模型。

**为每个成员分配钱包或在团队之间划分资金。** 不采用，因为团队就是计费身份。成员维度的分配会增加转账和再平衡流程，却不会改善用量归因；用量已经记录账号和 Runtime。

**预留调用可能产生的最高费用。** 不采用，因为输出 token 数未知，响应流中断后预留可能长期占用资金，而共享正余额准入已经提供预期的简单控制。接受的代价是有界并发透支。

**保存可兑换明文或从列表 API 返回明文。** 不采用，因为数据库或读取 API 权限会直接变成资金权限。一次性显示与 HMAC 查询限制了这种暴露。

**在客户端聚合最近一页用量。** 不采用，因为不完整分页无法生成团队总量、自然日范围或稳定的成员结果。

## 影响

团队可以兑换人民币，无需分配内部预算；每笔 settled 扣款都可以归因到组织、账号、Runtime、模型用量和结果余额。负余额可见，并会先消耗后续入账，之后调用才会恢复。没有合法用量的提供方响应流会保持待对账并暂不扣款；核对是以后应用唯一扣款的显式路径。平台运营人员可以创建兑换码、按提示／状态／批次查询、一次性导出和撤销未使用兑换码，团队成员则无法枚举平台兑换码库存。

## 测试

PostgreSQL 集成会在隔离数据库中应用迁移，并覆盖零余额拒绝、正余额放行、并发透支、负余额恢复、一次性与并发兑换、过期、撤销、跨组织隔离、自动与人工扣款幂等、角色限制摘要、成员分页记录和邀请权限。客户端测试覆盖 member-only 钱包视图、兑换错误、Owner 与管理员控制、日期范围、成员分页和邀请撤销。Admin 测试覆盖定点批次输入、一次性明文导出、状态／批次分页和未使用兑换码撤销。
