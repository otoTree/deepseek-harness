# Agent Note: 人民币模型用量分析

Status: implemented

[English](2026-09-16-cny-model-usage-analytics.md) | 中文

## 问题

管理后台的用量页面读取登录账号最近的原始记录，因此即使其他账号正在使用模型，平台管理员也可能看到空页面。模型价格和账本金额使用含义模糊的微单位名称，控制台则把它解释为美元。账本会丢弃兼容提供方已经报告的缓存输入和 reasoning（推理）计数，而且模型价格编辑后，如果没有不可变的价格快照，历史成本将无法解释。

## 决策

模型配置以人民币元／百万 token 接受普通输入、缓存输入和输出价格。API 把这些小数转换成整数微人民币元，其中 1 元等于 1,000,000 个存储单位。每次完成的 OpenAI 兼容 SSE 调用会保存输入、缓存输入、非缓存输入、输出、reasoning 和总 token 数，复制当时的三项价格，并记录普通输入、缓存输入、输出和总成本。Reasoning token 是输出 token 的子项，不会再次增加总 token。系统把每个成本分项四舍五入到最接近的微人民币元，再计算总和。

平台用量 API 读取 settled 记录，并提供有上限的汇总时间范围、Asia/Shanghai 每日序列、模型／账号／组织／用途分组，以及稳定的游标分页记录。货币为 `CNY` 的记录会贡献快照成本；兼容记录仍会贡献调用次数和已有 token 总量，但会被明确标记为未计价。管理后台默认展示最近 30 天，提供相同的筛选条件，并展示每次已计价调用的分项成本和价格快照。兼容用微美元模型及订阅字段保持独立，不参与人民币成本或模型调用准入。

[透明中转](../architecture/2026-09-15-transparent-model-relay.zh.md)继续负责认证转发和旁路观察。它会在发送前占用每个幂等键，使重复请求无法产生未记录的第二笔成本。成功响应流报告用量并到达 `[DONE]` 后才会完成用量持久化；持久化失败会保留占用以供核对，同时不改变中转响应。

## 备选方案

**把现有微美元字段改写为人民币。** 不采用，因为这会静默改变已保存值的币种，使现有记录无法解释。

**按照模型当前价格解析所有历史记录。** 不采用，因为管理员必须能够编辑模型价格，同时不改写已完成调用的含义。

**在浏览器中聚合最近 200 条记录。** 不采用，因为不完整的分页数据无法生成平台总量或稳定的时间序列结果。

**在分析账本中加入预算准入。** 不采用，因为统计是事后行为；缺少价格、观察器失败或订阅预算耗尽都不能阻止模型响应。

## 影响

平台管理员可以按时间、组织、账号、模型、用途和调用归因人民币成本，同时保留提供方的缓存和 reasoning 子项。后续价格编辑后，每条已计价 settled 记录仍可独立解释。不返回完整 OpenAI 兼容 SSE 用量事件的提供方仍然可用，但不会进入分析。没有 `currency = 'CNY'` 的现有兼容记录不会被指定虚构汇率，而是作为未计价 token 用量继续显示。

PostgreSQL 集成测试会把迁移应用到全新数据库，并验证详细结算、发送前幂等、无预算准入、平台权限、汇总、每日序列、分组和游标分页。聚焦观察器测试会保留缓存输入和 reasoning 计数，成本测试会固定分项舍入规则，时区无关的范围测试会固定 Asia/Shanghai 日期边界，管理后台生产构建会验证看板客户端包。
